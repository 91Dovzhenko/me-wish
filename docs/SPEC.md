# me:wish — функциональные требования

Метка `[Э1]`…`[Э5]` — этап из `ROADMAP.md`, на котором требование реализуется. Термины и статусы — в `DOMAIN.md`.

---

## 1. Вход и аккаунт

- **1.1 [Э1]** Вход через **Telegram** (основной) и **Google** (дополнительный). Вход по email — не делаем.
- **1.2 [Э1]** Вход через Telegram — **через бота по одноразовому коду** (D-111): приложение открывает `t.me/me_wish_bot?start=login_<код>`, пользователь жмёт «Start», вебхук бота (Edge Function) подтверждает вход, приложение обменивает код + секрет устройства на сессию Supabase. У Supabase нет встроенного провайдера Telegram.
- **1.3 [Э3]** Если пользователь вошёл через Google, в профиле есть кнопка **«Подключить Telegram»**: открывает бота по ссылке `t.me/<бот>?start=link_<одноразовый токен>`, бот привязывает свой чат к аккаунту. Без этой привязки бот не знает, чей это аккаунт.
- **1.4 [Э1]** Профиль: имя (можно изменить) и аватар (из Telegram/Google или своё фото с обрезкой по кругу, D-091), список по умолчанию для быстрого добавления, способы входа.
- **1.5 [Э1]** При первом входе автоматически создаётся список **«Мои желания»** и становится списком по умолчанию (D-048). Его можно переименовать, настроить или удалить.

## 2. Главный экран

- **2.1 [Э1]** Сетка обложек списков (как доски Pinterest) плюс дашборд сверху — одна тонкая строка (D-050, D-074): **активные** — количество и сумма в рублях; **исполнено за текущий календарный год** — количество и сумма в рублях. Других цифр нет. Навигация — как в ME:LVL (D-047): на компьютере левая боковая панель с разделами и списками, на телефоне шапка + плавающая кнопка «+».
- **2.2 [Э1]** На обложке списка: название, обложка (автоматический коллаж из фото 4 последних желаний или иконка списка, D-095), количество карточек, общая сумма в рублях, дата последнего добавления, дата события (если указана) — меткой в углу обложки. Все обложки одного размера (D-074). У списка есть иконка и цвет (D-075) — в боковом меню и на обложке пустого списка.
- **2.3** Списки разделены на разделы:
  - **[Э1] Мои** — где я единственный участник;
  - **[Э2] Совместные** — где несколько редакторов;
  - **[Э2] Со мной поделились** — чужие списки, где я зритель (название раздела уточняется, см. `OPEN_QUESTIONS.md`);
  - **[Э5] Архив** — архивные списки.
- **2.4 [Э1]** Кнопка **«Добавить»** доступна всегда (плавающая кнопка):
  - на главном экране — сначала выбор списка (по умолчанию предлагается список по умолчанию);
  - внутри списка — добавляет в этот список (список уже выбран в «Подробнее», D-073).
- **2.5 [Э1]** Создание списка — «+ Новый список»: на компьютере в боковом меню под списками, на телефоне — в разделе «Мои списки» (D-076).

## 3. Списки

- **3.1 [Э1]** Поля списка: название (обязательно), описание, дата события (необязательно, выбор в календаре — D-090), иконка и цвет (D-075), обложка: «Коллаж» из фото 4 последних желаний или «Иконка» (D-095).
- **3.2 Настройки списка:**
  - **[Э4] Видимость:** приватный / доступ по ссылке (D-079; на этапе 1 все списки приватные). (Публичный профиль — не делаем.)
  - **[Э4] Бронирование:** вкл/выкл.
  - **[Э4] Режим анонимности броней:** даритель выбирает сам / только анонимно / только открыто.
  - **[Э2] Голосование:** вкл/выкл.
  - Настройки можно менять после создания.
- **3.3 [Э1]** Внутри списка — сводка по этому списку (активные: количество и сумма; исполнено: количество и сумма) и сетка карточек.
- **3.4 [Э1] Сортировка:** по умолчанию — по приоритету (сверху «Мечта», при равном — сначала новые, D-057); также по цене (по возрастанию/убыванию), по дате добавления, по приоритету, по статусу. Переключатель **«Исполненные»** (купленные/подаренные) — скруглённый чип (D-074). Переключение «сетка/список» не нужно — только сетка.
- **3.4a [Э1] Удаление списка (D-082):** подтверждение «Удалить список и N желаний?», желания уходят в корзину. Последний список удалить нельзя. Удалён список по умолчанию — по умолчанию становится первый из оставшихся.
- **3.5 [Э2]** Удалить совместный список может любой редактор (с подтверждением).
- **3.6 [Э5]** Архивирование списка: исчезает с главного экрана, остаётся в разделе «Архив» как история исполненных желаний. Можно вернуть из архива.
- **3.7** Дата события **не меняет статусы карточек автоматически**: всё отмечает владелец вручную.

## 4. Добавление желаний

### 4.1 Форма добавления в вебе [Э1] (D-059, D-061–D-063)
Автозаполнения по ссылке нет: карточку заполняет сам человек, форма сделана так, чтобы это занимало секунды.
- **Один экран:** фото, **название** (единственное обязательное поле, отмечено красной звёздочкой; подписей «необязательно» нет, D-073), цена в рублях (D-072), ссылка на товар (без кнопки «Вставить»), описание (размер, цвет, модель, пожелания).
- **Под основными полями (всегда видны, блока «Подробнее» нет — D-088):** приоритет (по умолчанию 3 «Хочу», D-057), выбор списка — уже выбран: с главного экрана — список по умолчанию из профиля, изнутри списка — этот список (D-073).
- **Фото:** из галереи / скриншот, на компьютере — ещё вставка из буфера (Cmd+V) и перетаскивание. Выбрать можно только одно фото; у выбранного — «Обрезать», «Другое фото», «Удалить фото» (D-088). Сразу после выбора — обрезка: только квадрат, фото можно приближать и двигать (телефон — двумя пальцами, компьютер — ползунок, колесо, трекпад; D-066). Сжатие до ~800 px по длинной стороне — в браузере, до загрузки в Storage. Принимаются только картинки JPG / PNG / WEBP / HEIC до 20 МБ, рядом подсказка о формате (D-084).
- **Ссылка** необязательна, но стоит сразу под названием: по ней работает «Перейти в магазин». Сайт по ссылке не загружается. При сохранении из ссылки убираются рекламные и служебные метки (`cpc`, `utm_*`, `spm`, `at`, `sh` и т. п.), размер / продавец / вариант остаются.
- Подходит и для желаний без ссылки: «хочу в аквапарк», «билеты в театр».

### 4.2 (объединено с 4.1)
Отдельных режимов «по ссылке» и «вручную» больше нет — одна форма.

### 4.3 Через Telegram-бота [Э3] (D-064)
1. Пользователь отправляет боту **фото или скриншот товара с подписью**: название, цена и ссылка в любом порядке. Можно и просто текстом, без фото.
2. Бот разбирает подпись: ссылку находит сам; **цена — только явная** (число на отдельной строке или рядом с «₽», «р», «руб»), иначе пустая — чтобы не принять модель («Rode 1380») за цену; остальной текст — название.
3. Без подписи бот коротко спрашивает название (цену и ссылку — можно пропустить).
4. Бот спрашивает: «Добавить в «<список по умолчанию>»?» — **[Да]** / **[Выбрать другой]** (списки, где пользователь редактор).
5. Карточка создаётся. Бот показывает, что понял: фото, название, цена, ссылка — и кнопки **[Указать цену]** (если цены нет) / **[Изменить]** / **[Открыть в me:wish]**.
6. Фото из Telegram сжимается до ~800 px и сохраняется в Storage.
7. Текст из кнопок «Поделиться» приложений магазинов отдельно не разбираем — это обычная ссылка с текстом.
8. Если чат не привязан к аккаунту — бот предлагает войти или привязать аккаунт.

### 4.4 Android — меню «Поделиться» [Э3, низкий приоритет]
- PWA с `share_target` в манифесте: на Android установленное приложение появляется в системном меню «Поделиться». На iOS это невозможно (Safari не поддерживает Web Share Target).

### 4.5 Разбор ссылок — не делаем (D-059)
- Сайты магазинов по ссылке не загружаются, функции `parse-link` нет. Причина и данные — `tech/parsing-research.md` (исследование 002).
- Цена **не обновляется** после создания (D-005).

## 5. Карточка желания

- **5.1 [Э1]** Поля: картинка (квадрат, D-066), название, цена в рублях (D-072), описание (размер, цвет, модель — D-063), ссылка на товар, приоритет (1–5), статус, дата добавления. Отдельного комментария нет.
- **5.2 [Э1]** В сетке — компактная карточка в стиле Яндекс Маркета: квадратное фото, название (максимум 2 строки), цена, приоритет (значок-сердечки, у 4–5 — акцентная метка, D-056), статус.
- **5.2a [Э1] Приоритет:** 1 «Можно и без», 2 «Было бы неплохо», 3 «Хочу», 4 «Очень хочу», 5 «Мечта». Новая карточка — 3 «Хочу» (D-057). Меняется в одно нажатие в открытой карточке.
- **5.3 [Э1]** Открытая карточка — **окно поверх списка** (D-067): на телефоне шторка на всю высоту, на компьютере окно по центру; у карточки свой адрес. Порядок (D-068, D-087): название (целиком) → цена и приоритет в одной строке (нажатие на приоритет — выбор уровня) → описание (4 строки + «Ещё») → действия. Главная кнопка — «Перейти в магазин» (на телефоне закреплена внизу); статус — выпадающий список (D-069); меню «•••» — «Редактировать», «Переместить», «Удалить» (D-071).
- **5.4 [Э1] Валюта:** все цены в рублях, выбора валюты нет (D-072). Другие валюты — бэклог.
- **5.5 [Э1] Статусы:** в интерфейсе — «В желаниях», «Куплено», «Подарили» (D-058, D-070); см. `DOMAIN.md` §2. Владелец меняет статус вручную выпадающим списком, в любую сторону (D-069). Завершённые карточки уходят в группу «Исполнено» внутри списка.
- **5.6 [Э4]** Если владелец отмечает «Куплено» на забронированной карточке — предупреждение «Это желание уже забронировано. Точно купили сами?». После подтверждения бронь снимается, а даритель получает уведомление (если оставил контакт).
- **5.7 [Э1] Удаление:** без подтверждения — карточка уходит в **корзину** на 30 дней (тост «Удалено · Отменить», D-080), потом удаляется автоматически. В корзине — «Восстановить» и «Очистить корзину» (с подтверждением). Если списка карточки уже нет — при восстановлении выбор списка, предвыбран список по умолчанию (D-082).
- **5.8 [Э1]** Простой перенос карточки в другой свой список — «•••» → «Переместить» (D-071). **[Э5]** Перенос в совместные списки и **дублирование** (связанная копия) — см. раздел 8.

## 6. Совместные списки и голосование [Э2]

- **6.1** Роли: **редактор** и **зритель** (см. `DOMAIN.md` §4). Владелец отдельно не выделяется — у всех редакторов одинаковые права, включая приглашение участников и удаление списка.
- **6.2** Приглашение: ссылка-приглашение с выбором роли (действует для зарегистрированных пользователей; после входа список появляется в разделе «Совместные» или «Со мной поделились»).
- **6.3** Если голосование включено, на каждой карточке у редактора кнопки **«Одобряю» / «Отклоняю»**; на телефоне также свайп вправо/влево.
- **6.4** Голосуют только редакторы; зрители и гости голоса не видят.
- **6.5** Карточки внутри списка группируются:
  - **Одобрено всеми** — все редакторы одобрили;
  - **Нужно решить** — голоса расходятся;
  - **Отклонено всеми** — все отклонили (группа свёрнута);
  - **Ждёт голосов** — не все проголосовали.
- **6.6** Голос можно поменять в любой момент; для «Нужно решить» итог достигается, когда кто-то меняет решение.
- **6.7** Если в список добавили нового редактора, его голоса нет — карточки возвращаются в «Ждёт голосов» до его решения.

## 7. Публичные ссылки и бронирование [Э4]

### 7.1 Публичная ссылка
- Список с видимостью «по ссылке» имеет общую ссылку `/l/<slug>`; её можно кинуть в общий чат.
- Гость без регистрации видит: название, описание, дату события, карточки (кроме удалённых), статус брони каждой карточки.
- Владелец тоже может открыть свою ссылку как гость и даже забронировать — ограничений нет.

### 7.2 Бронирование гостем
1. Гость нажимает «Забронировать» на карточке.
2. Форма:
   - имя (если бронь открытая);
   - открыто или анонимно (если список разрешает выбор);
   - контакт для уведомлений — **необязательно**: кнопка «Получать уведомления в Telegram» или поле email.
3. Бронь создаётся. Браузеру гостя выдаётся гостевой токен (cookie/localStorage) — по нему с того же устройства гость видит «Мои брони» и может отменить их.
4. Количество броней у одного гостя не ограничено. Кто первый — того и подарок.

### 7.3 Уведомления в Telegram (как это работает)
Бот не может первым написать человеку, который ему не писал. Поэтому:
1. После брони гость нажимает **«Получать уведомления в Telegram»** — открывается `t.me/<бот>?start=g_<гостевой токен>`.
2. В Telegram гость нажимает **Start**. Бот получает токен, связывает чат с гостем.
3. Бот сразу присылает подтверждение: **для кого, какое событие и дата, что забронировано** (картинка, название, цена, ссылка) и **персональную ссылку** с текстом: «Чтобы изменить или отменить бронь, переходите по этой ссылке — она только ваша».
4. Дальше бот присылает сообщения при каждой новой брони и отмене этого гостя («Вы отменили X и забронировали Y»), а также если владелец купил забронированное сам.
5. Если гость уже зарегистрирован в me:wish и вошёл в аккаунт — бронь привязывается к аккаунту, токен не нужен.

### 7.4 Уведомления по email
- Те же сообщения, что в Telegram, письмом. Сервис отправки — см. `OPEN_QUESTIONS.md`.

### 7.5 Управление бронями без аккаунта
- Общая ссылка остаётся общей. Персональная ссылка `/b/<токен>` — только для управления своими бронями: показывает список, на карточках свои брони отмечены «Вы забронировали», можно отменить и забронировать другое.
- Токен длинный и случайный, в базе хранится хэш. Знание общей ссылки не даёт доступа к чужим броням.
- Срок брони не ограничен, автоснятия нет.

### 7.6 Что кто видит
| | Факт брони | Имя дарителя | Контакт дарителя |
|---|---|---|---|
| Открытая бронь | все | владелец, редакторы, гости, зрители | никто, кроме самого дарителя |
| Анонимная бронь | все | никто («Анонимно») | никто, кроме самого дарителя |

Факт брони показывается владельцу сразу.

### 7.7 После вручения
- Владелец сам отмечает карточку «Подарено». Анонимность сохраняется.

## 8. Связанные карточки в нескольких списках [Э5]

- **8.1** Карточку можно **перенести** в другой список или **продублировать** (связанная копия — одно желание в нескольких списках).
- **8.2** При дублировании можно сразу выбрать приоритет для нового списка.
- **8.3 Общие поля** (меняются везде): название, картинка, ссылка, описание, цена, статус (бронь, покупка, подарок).
- **8.4 Свои для каждого списка:** приоритет, позиция (D-063).
- **8.5** Общие поля может менять любой редактор любого списка, где есть карточка.
- **8.6** При удалении карточки из списка, где она связана с другими, спрашиваем: **«Удалить только из этого списка» / «Удалить везде»** (как в «Фото» на iPhone).
- **8.7** Бронь в одном списке отмечает карточку забронированной во всех списках. Имя дарителя показывается по настройкам анонимности того списка, где сделана бронь; контакт не раскрывается нигде.

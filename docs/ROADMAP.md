# Дорожная карта

Каждый этап заканчивается тем, что владелец может пользоваться результатом. Следующий этап начинается после приёмки предыдущего.

Каждая фича внутри этапа проходит цикл из `WORKFLOW.md`: сверка → интервью → ТЗ на дизайн → дизайн → ТЗ для Claude Code → реализация → разбор отчёта.

| Этап | Суть | Кто пользуется | Ориентир |
|---|---|---|---|
| 0 | Подготовка, проект Claude, техническое исследование | — | 1 сессия |
| 1 | Личный вишлист в вебе | автор | 2–4 сессии |
| 2 | Telegram-бот | автор | 1–2 сессии |
| 3 | Совместные списки и голосование | автор + жена | 2 сессии |
| 4 | Публичные ссылки и бронирование | + друзья и родственники | 2–3 сессии |
| 5 | Связанные карточки, архив, история | все | 1–2 сессии |
| 6 | Telegram Mini App и улучшения | все | позже |

«Сессия» — один рабочий заход с Claude Code. Самая большая неизвестность — разбор маркетплейсов на этапе 0–1.

---

## Этап 0 — подготовка

- Репозиторий `me-wish`, проект Vite + React + TS + Tailwind, деплой на GitHub Pages.
- Проект в Supabase, локальные миграции, `.env.example`.
- Создан Telegram-бот через @BotFather (нужен уже для входа), домен прописан для Login Widget.
- **Техническое исследование разбора ссылок** → `docs/tech/parsing-research.md`:
  - для Ozon, Wildberries, Яндекс Маркета, обычного магазина, AliExpress: что отдаётся на запрос с сервера Supabase Edge Functions (антибот? JSON-LD? Open Graph? открытые API по артикулу?);
  - выбор стратегии для каждого и запасной вариант;
  - нужен ли платный прокси или внешний сервис — если да, остановиться и согласовать с владельцем.
- Каркас PWA (манифест, иконки).

**Готово, когда:** пустое приложение открывается по адресу на GitHub Pages, исследование записано, стратегия разбора согласована.

## Этап 1 — личный вишлист в вебе

- Вход через Telegram и Google.
- Главный экран: дашборд + сетка «Мои списки».
- Создание, редактирование, удаление списка (название, описание, дата, обложка, видимость).
- Добавление по ссылке с автозаполнением (`parse-link`), копирование картинки в Storage.
- Ручное добавление (короткая и расширенная форма).
- Карточка: приоритет, комментарий, валюта, статусы «Куплено сам» / «Подарено», группа «Исполнено».
- Сортировка, переключатель «Показывать завершённые», сумма списка.
- Корзина на 30 дней.
- Список по умолчанию в профиле.
- PWA: добавляется на главный экран iPhone и в Dock.

**Готово, когда:** автор неделю пользуется сервисом вместо чата в Telegram.

## Этап 2 — Telegram-бот

- Вебхук бота в Edge Function.
- Привязка чата к аккаунту (автоматически при входе через Telegram, через «Подключить Telegram» для Google).
- Отправка ссылки → выбор списка → создание карточки → ответ с превью.
- «Добавить желание» без ссылки.
- Комментарий к карточке из бота.
- (Низкий приоритет) Android share target.

**Готово, когда:** автор добавляет желания с телефона в 2–3 нажатия через бота.

## Этап 3 — совместные списки и голосование

- Роли «редактор» и «зритель», приглашение по ссылке.
- Разделы «Совместные» и «Со мной поделились».
- Настройка «голосование вкл/выкл».
- Кнопки и свайпы «Одобряю / Отклоняю», группы карточек по итогам голосования.

**Готово, когда:** автор и жена выбрали что-то для дома через голосование.

## Этап 4 — публичные ссылки и бронирование

- Публичная страница списка `/l/<slug>` для гостей.
- Настройки бронирования и анонимности.
- Бронь гостем, гостевой токен, «Мои брони».
- Уведомления в Telegram через стартовый токен, персональная ссылка управления.
- Уведомления по email (после выбора сервиса).
- Сценарий «Куплено сам» на забронированной карточке.

**Готово, когда:** вишлист на день рождения разослан друзьям, и они бронировали без проблем.

## Этап 5 — связанные карточки, архив, история

- Перенос и дублирование карточек между списками.
- Общие и свои поля, удаление «из этого списка / везде».
- Синхронизация броней и статусов.
- Архив списков, раздел «Архив», история исполненных желаний.

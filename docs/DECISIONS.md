# Журнал решений

Формат: номер, дата, решение, причина. Новые решения — внизу. Отменённое решение не удаляем, а помечаем «Заменено D-xxx».

## Продукт

**D-001 · 2026-11-22 · Название — me:wish** (в технических именах `me-wish`). Продолжение линейки me:level.

**D-002 · 2026-11-22 · Ключевая фича — создание карточки по ссылке без предпросмотра.** Карточка создаётся сразу, правки потом. Причина: длина пути добавления — главная боль существующих сервисов. *Заменено D-059.*

**D-003 · 2026-11-22 · Несколько независимых списков, как доски Pinterest.** Отдельной сущности «Событие» нет: список под событие с датой и описанием. Причина: знакомая механика, меньше сущностей.

**D-004 · 2026-11-22 · Любое желание можно сохранить, даже только с названием.**

**D-005 · 2026-11-22 · Цены автоматически не обновляются.**

**D-006 · 2026-11-22 · Характеристики товара (размер, цвет, модель) — свободный комментарий, а не автоопределение.** *Уточнено D-063: пишутся в поле «Описание».* Причина: автоопределение вариантов ненадёжно и усложняет добавление.

**D-007 · 2026-11-22 · Удаление карточки — в корзину на 30 дней. Архива карточек нет:** роль архива играют статусы «Куплено сам» / «Подарено». Архив есть только для списков.

**D-008 · 2026-11-22 · Приоритет — 1–5, свой в каждом списке.**

**D-009 · 2026-11-22 · Валюты RUB, USD, EUR.** Сумма списка — только по рублям, остальные показываются отдельно, без конвертации.

**D-010 · 2026-11-22 · Только сетка карточек**, без переключения на вид списка. Поиск и фильтры — не в MVP, есть сортировка и переключатель «Показывать завершённые».

## Доступ и роли

**D-011 · 2026-11-22 · Две роли: редактор и зритель.** Владелец и редактор объединены, у всех редакторов равные права, включая удаление списка. Причина: в совместных списках (пара, друзья) иерархия не нужна.

**D-012 · 2026-11-22 · Голосуют только редакторы.** Решение по карточке — единогласное, голос у каждого свой. Гости и зрители голоса не видят.

**D-013 · 2026-11-22 · Бронирование и голосование — независимые настройки списка.**

**D-014 · 2026-11-22 · Видимость списка: приватный или по ссылке.** Публичного профиля нет.

## Бронирование

**D-015 · 2026-11-22 · Бронь без регистрации; контакт необязателен.** Без контакта управлять бронью можно только с того же устройства (гостевой токен в браузере).

**D-016 · 2026-11-22 · Общая ссылка на список + персональная ссылка для управления своими бронями.** Причина: одну ссылку кидают в общий чат, персональная защищает чужие брони.

**D-017 · 2026-11-22 · Анонимность:** владелец списка задаёт «выбор дарителя / только анонимно / только открыто». Контакт дарителя не видит никто, кроме него самого.

**D-018 · 2026-11-22 · Факт брони виден всем, включая владельца, сразу.** Скрывать факт до праздника не нужно.

**D-019 · 2026-11-22 · Срока брони и автоснятия нет. Число броней у одного дарителя не ограничено.**

**D-020 · 2026-11-22 · «Подарено» отмечает владелец вручную;** дата события статусы автоматически не меняет. Причина: день рождения могут отмечать позже даты.

**D-021 · 2026-11-22 · Если владелец купил забронированное сам** — предупреждение, после подтверждения бронь снимается, а даритель получает уведомление.

**D-022 · 2026-11-22 · Владелец может открыть свою публичную ссылку и бронировать** — без искусственных ограничений.

**D-023 · 2026-11-22 · Уведомления дарителю в Telegram — через кнопку, которая открывает бота со стартовым токеном.** Причина: бот не может написать первым.

**D-024 · 2026-11-22 · Совместные подарки и сбор денег — не в первой версии** (бэклог).

## Связанные карточки

**D-025 · 2026-11-22 · Общие поля:** название, картинка, ссылка, описание, цена, статус. **Свои:** приоритет, комментарий. *Уточнено D-063: комментария нет, своё поле — только приоритет.* Общие поля меняет любой редактор.

**D-026 · 2026-11-22 · При удалении связанной карточки спрашиваем «из этого списка / везде».**

**D-027 · 2026-11-22 · Бронь синхронизируется во всех списках, имя автора — по настройкам списка, где сделана бронь.**

## Техника

**D-028 · 2026-11-22 · Стек:** React + TypeScript + Vite, Supabase (Postgres, Auth, Storage, Edge Functions), GitHub Pages. Причина: опыт владельца с этим стеком в me:level, бесплатные тарифы.

**D-029 · 2026-11-22 · Формат — PWA, основной интерфейс — веб.** Нативного приложения нет (аккаунт разработчика Apple из России сложен и платный). Telegram Mini App — дополнительный интерфейс позже.

**D-030 · 2026-11-22 · Вход: Telegram основной, Google дополнительный.** Email-вход не делаем.

**D-031 · 2026-11-22 · В меню «Поделиться» на iOS не встраиваемся** (Safari не поддерживает Web Share Target). Быстрая команда iOS — в бэклог. На Android share target — дешёвое дополнение на этапе 2.

**D-032 · 2026-11-22 · Картинки товаров копируются в Storage и сжимаются.** Причина: ссылки маркетплейсов могут перестать работать или блокировать хотлинк. *Уточнено D-062: картинки загружает сам пользователь, сжимаются в браузере.*

**D-033 · 2026-11-22 · 152-ФЗ сейчас не учитываем** — сервис для близкого окружения. Вернуться к вопросу перед публичным запуском.

**D-034 · 2026-11-22 · Порядок этапов:** ядро → бот → совместные списки → публичные ссылки и брони → связанные карточки. Причина: первыми продуктом пользуются автор с женой.

## Процесс

**D-035 · 2026-11-22 · Instagram не поддерживаем для автозаполнения.** Причина: сервер загружает ссылку без входа в аккаунт и почти ничего не получает.

**D-036 · 2026-11-22 · Цикл работы:** сверка → интервью → ТЗ на дизайн → дизайн в Artifacts → ТЗ для Claude Code → реализация → разбор отчёта. Продуктовая работа — в проекте Claude, код — в Claude Code, общая локальная папка. Подробно в `WORKFLOW.md`.

## Этап 0 — подготовка

**D-037 · 2026-11-22 · Адрес сайта — бесплатный `<логин>.github.io/me-wish`, свой домен подключим позже** (Q-04 решено). Причина: бесплатно, ничего не нужно покупать. Помнить: при смене домена надо будет перенастроить домен бота для входа через Telegram, а старые ссылки на списки перестанут работать.

**D-038 · 2026-11-22 · Репозиторий `me-wish` на GitHub — публичный.** Причина: на бесплатном тарифе GitHub Pages работает только с публичными репозиториями. Секреты в код не попадают.

**D-039 · 2026-11-22 · Ссылки в приложении чистые, без `#`** (например, `…/me-wish/l/abc`). Технически через приём с `404.html` на GitHub Pages. Причина: ссылки на списки будут рассылать гостям, они должны выглядеть аккуратно.

**D-040 · 2026-11-22 · Supabase — отдельный проект `me-wish` на бесплатном тарифе, регион Central EU (Frankfurt).** Причина: на аккаунте занят один проект из двух бесплатных; Франкфурт ближе всего к пользователям в России.

**D-041 · 2026-11-22 · Telegram-бот: имя «me:wish», адрес `@mewish_bot`.** Если адрес занят — `@me_wish_bot` или `@mewishlist_bot`.

**D-042 · 2026-11-22 · Тестовые ссылки для исследования разбора (3 Ozon, 3 WB, 3 Яндекс Маркет, 3 обычных магазина, 1 AliExpress) собирает владелец** из реальных желаний.

**D-043 · 2026-11-22 · Всё на GitHub владелец делает сам руками** (создание и публикация репозитория через GitHub Desktop, настройки Pages, переменные Actions, push) по пошаговым инструкциям из проекта Claude. Claude Code только готовит код и коммиты. Причина: владельцу так удобнее и понятнее.

**D-044 · 2026-11-22 · Настройки Supabase при создании проекта:** Data API включён; автоматическая выдача API-доступа к новым таблицам и автоматическое включение RLS — включены. Причина: RLS как страховка по умолчанию; без автоматической выдачи доступа запросы из приложения падали бы с ошибкой прав, если миграция забудет GRANT.

**D-045 · 2026-11-22 · Ключ Supabase для приложения — publishable key (`sb_publishable_…`)**, переменная по-прежнему называется `VITE_SUPABASE_ANON_KEY`. В GitHub Actions адрес и ключ хранятся как variables, а не secrets: они публичные и всё равно попадают в код сайта. Секретный ключ (secret / service_role) — только в секретах Supabase, никогда в GitHub и в браузере.

## Этап 1 — личный вишлист

**D-046 · 2026-11-23 · Визуальный стиль — семейство ME:LVL.** me:wish наследует стиль ME:LVL (а тот — Things): светлый спокойный фон, белые блоки с большим скруглением, чёрный текст, жирные заголовки, минимум декора. Плюс аккуратные цветовые акценты с лёгким градиентом местами (как в MoneyWiz), а не везде. Референсы — Things, Pinterest, ME:LVL, MoneyWiz (`docs/design/references-private/`). Заменяет «база — Яндекс Маркет» из Q-08; карточки товаров по-прежнему в духе Маркета (фото, цена крупно, название в 2 строки).

**D-047 · 2026-11-23 · Навигация — как в ME:LVL.** Компьютер: левая боковая панель (разделы и списки, активный пункт подсвечен акцентом), контент — в большой белой скруглённой панели. Телефон: шапка с логотипом и иконкой настроек/профиля, плавающая круглая кнопка «+» внизу справа, без нижней панели вкладок. Точная раскладка главного экрана телефона — на дизайне.

**D-048 · 2026-11-23 · При первом входе автоматически создаётся список «Мои желания»** и становится списком по умолчанию. Его можно переименовать, настроить или удалить.

**D-049 · 2026-11-23 · ~~Карточка желания — отдельная страница со своим адресом** (можно поделиться ссылкой), а не окно поверх списка. Статус: гипотеза, окончательно — после дизайна.~~ *Заменено D-067: окно поверх списка.*

**D-050 · 2026-11-23 · Дашборд на главной:** активные желания (количество + сумма в рублях) и исполнено за текущий календарный год (количество + сумма в рублях). Активные = статус `active` или `booked`, не в корзине; исполненные = `purchased` или `gifted`. Внутри каждого списка — такая же сводка по этому списку. Других цифр на главной нет. (Q-07 решено.)

**D-051 · 2026-11-23 · Обложка списка — автоматический коллаж из 3–4 фото последних добавленных карточек** (не случайных, чтобы обложка не «прыгала»). В настройках списка можно выбрать одну карточку обложкой. Загрузки своей картинки нет. (Q-05 решено.)

**D-052 · 2026-11-23 · Палитра: светлая нейтральная основа + два акцента — лайм и лаванда.** Фон почти белый, поверхности светло-серые, текст почти чёрный; лайм — главный акцент (кнопка «+», активные элементы, главные действия), лаванда — второй акцент и мягкие градиенты местами. Референс — dreamboard, черновик — `docs/design/references-private/palette-draft.png`. Наследование ME:LVL концептуальное: структура и ощущение, а не точные шрифты и цвета.

**D-053 · 2026-11-23 · Корзина не выносится на главный экран** — она в общем меню (профиль / настройки), на компьютере — неприметным пунктом внизу боковой панели.

**D-054 · 2026-11-23 · Страница карточки: главное действие — «Перейти в магазин», статусы («Куплено», «Подарили», см. D-058) — тоже на виду**, отдельными кнопками. Редактирование и удаление — в меню «•••».

**D-055 · 2026-11-23 · Тёмная тема — не в этапе 1** (бэклог). Цвета в коде всё равно через переменные, чтобы её можно было добавить позже.

**D-056 · 2026-11-23 · Приоритет показывается словами и значками.** 5 уровней (D-008): 1 «Можно и без», 2 «Было бы неплохо», 3 «Хочу», 4 «Очень хочу», 5 «Мечта». В сетке — компактный значок из заполненных сердечек (или точек/огоньков — выбрать на дизайне, владелец склоняется к сердечкам); у уровней 4 и 5 — заметная метка акцентным цветом. Главный сценарий: дарителю сразу видно, чего человек хочет сильнее всего.

**D-057 · 2026-11-23 · Новая карточка получает приоритет 3 «Хочу».** Внутри списка сортировка по умолчанию — по приоритету (сверху «Мечта»), при равном — сначала новые. Фильтры по приоритету и статусу — бэклог.

**D-058 · 2026-11-23 · Названия статусов в интерфейсе: «Хочу», «Куплено», «Подарили».** «Куплено сам» не используем (звучит странно и зависит от рода). В базе — по-прежнему `active` / `purchased` / `gifted` (DOMAIN). На странице карточки — кнопки «Куплено» и «Подарили»; у исполненной карточки — «Вернуть в желания».

## Отказ от автозаполнения (по итогам исследования 002)

**D-059 · 2026-11-23 · Автозаполнение карточки по ссылке не делаем. Заменяет D-002.** Карточку заполняет сам человек: в вебе через быструю форму, в боте — скриншот с подписью. Функции `parse-link` нет, сайты магазинов мы не загружаем. Автозаполнение — в бэклоге с пометкой «маловероятно». Причина: исследование 002 — с сервера Ozon, Яндекс Маркет и Lamoda не отдают ничего, у WB нет цены, AliExpress работает с перебоями. «Вставил ссылку — всё заполнилось само» бесплатно не получается, а частичное автозаполнение — сложность и хрупкость без нужного результата.

**D-060 · 2026-11-23 · Платный сервис разбора не нужен** (Q-01 решено). Следует из D-059.

**D-061 · 2026-11-23 · Ссылка на товар — главный артефакт карточки, но необязательна.** В форме стоит сразу под названием; по ней работает «Перейти в магазин» — так даритель покупает именно этот товар у этого продавца. Без ссылки можно (D-004: «массаж», «поездка на море»). При сохранении из ссылки убираются рекламные и служебные метки (`cpc`, `utm_*`, `spm`, `at`, `sh` и т. п.), а размер, продавец и вариант остаются. Значок или название магазина отдельно не показываем — видно по фото и ссылке.

**D-062 · 2026-11-23 · Форма добавления — один экран:** фото, название (обязательно), цена (+ валюта), ссылка, описание. Под «Подробнее» — приоритет и выбор списка (если добавляют с главной). Фото — из галереи, скриншот или вставка из буфера на компьютере, сразу с обрезкой. Сжатие до ~800 px — в браузере до загрузки в Storage.

**D-063 · 2026-11-23 · Одно текстовое поле «Описание»** вместо пары «описание + комментарий»: размер, цвет, модель, пожелания. Отдельного комментария нет. Причина: без автозаполнения два поля дублируют друг друга.

**D-064 · 2026-11-23 · Бот: скриншот с подписью → карточка.** Человек отправляет боту фото/скриншот, в подписи — название, цена и ссылка в любом порядке. Ссылку бот находит сам; остальной текст — название. Цена — только явная: число на отдельной строке или рядом с «₽», «р», «руб». Иначе цена пустая (защита от моделей вроде «Rode 1380»). Бот показывает, что понял, с кнопками «Указать цену» / «Изменить» / «Открыть в me:wish». Без подписи — переспрашивает название. Можно прислать и просто текст (без фото). Текст из кнопок «Поделиться» приложений магазинов отдельно не разбираем.

## Дизайн этапа 1 — разбор итерации 2

**D-066 · 2026-11-23 · Фото товара везде квадратное** — в сетке, в открытой карточке, на экране входа; фото заполняет квадрат целиком. Обрезка — только квадрат (режим «Свободно» убран), фото можно приближать и двигать внутри рамки: на телефоне — двумя пальцами, на компьютере — ползунок масштаба, колесо мыши и жест трекпада. Причина: было непонятно, сколько места занимает фото, и свободная обрезка ломала карточки.

**D-067 · 2026-11-23 · Открытая карточка — окно поверх списка, а не отдельная страница. Заменяет D-049.** Телефон — шторка снизу на всю высоту (как форма добавления), компьютер — окно по центру. У карточки остаётся свой адрес, чтобы ссылкой можно было поделиться (рекомендация, владелец не возражал).

**D-068 · 2026-11-23 · Порядок в карточке: название → цена → приоритет → описание → действия** (на телефоне и компьютере). «Перейти в магазин» — главная кнопка (на телефоне закреплена внизу). Приоритет — одна компактная строка: мелкие сердечки близко друг к другу, справа слово уровня, без отдельной плашки. Длинное название в карточке — целиком; в сетке — максимум 2 строки с многоточием. Длинное описание — первые 4 строки и «Ещё».

**D-069 · 2026-11-23 · Статус меняется выпадающим списком, а не двумя кнопками. Уточняет D-054, D-058.** Статус можно менять в любую сторону в любой момент (например, вернуть «Куплено» обратно, если товар вернули). Причина: кнопки у пальца — риск случайного нажатия, и было непонятно, как отменить.

**D-070 · 2026-11-23 · Статус `active` в интерфейсе — «В желаниях»** (было «Хочу»). Итого: «В желаниях» / «Куплено» / «Подарили». Причина: «Хочу» — это ещё и приоритет 3, названия путались.

**D-071 · 2026-11-23 · Меню «•••» карточки: «Редактировать», «Переместить», «Удалить»** (удалить — в корзину). Короткие названия. Простой перенос карточки между своими списками — этап 1; дублирование и связанные копии — по-прежнему этап 5.

**D-072 · 2026-11-23 · Все цены — в рублях, выбора валюты нет.** Доллары и евро — в бэклог. Уходит и пометка «+ N в другой валюте». Заменяет часть D-062 и SPEC §5.4. Причина: другие валюты — редкий случай, сервис для автора с женой.

**D-073 · 2026-11-23 · Форма добавления: без кнопки «Вставить»** (вставка через обычное меню телефона или Cmd+V). Обязательное поле (только «Название») — красная звёздочка; подписей «необязательно» нет. В «Подробнее» список уже выбран: изнутри списка — этот список, с главной — список по умолчанию из профиля.

**D-074 · 2026-11-23 · Главная:** все карточки списков одного размера, дата события — меткой в углу обложки. Дашборд — одна тонкая строка («Активные 21 · 186 400 ₽ | Исполнено в 2026: 7 · 54 300 ₽»), на телефоне и компьютере. Уточняет D-050 (цифры те же). «Исполненные» в списке — скруглённый переключатель-чип вместо квадратного чекбокса.

**D-075 · 2026-11-23 · У списка есть иконка и цвет:** при создании выбираются из ~30 иконок на разные случаи и палитры цветов. Иконка видна в боковом меню и на обложке пустого списка. Обложка с фото — по-прежнему коллаж (D-051).

**D-076 · 2026-11-23 · Компьютер:** логотип пишется капсом — ME:WISH. «+ Новый список» — в боковом меню под списками; большой плитки «Новый список» на главной нет. Корзина — в меню профиля внизу боковой панели (уточняет D-053). «Добавить желание» — справа вверху контентной панели.

**D-077 · 2026-11-23 · На холсте раздел «Компоненты» заменяется разделом «Спецификация»**, как в ME:LVL: цвета, шрифты, отступы, скругления, компоненты во всех состояниях.

**D-078 · 2026-11-23 · Этап 1 дорисовывается целиком — все экраны, сценарии и состояния — до первого ТЗ для Claude Code.** Остальные этапы проектируются своим циклом, когда до них дойдём.

**D-079 · 2026-11-23 · Видимость «по ссылке» и «Поделиться» — не в этапе 1, а в этапе 4** (вместе со страницей для гостей). Причина: без гостевой страницы переключатель ничего не делает.

**D-080 · 2026-11-23 · Удаление карточки — без вопроса «Точно?»:** карточка сразу уходит в корзину, внизу тост «Удалено · Отменить». В корзине — «Восстановить» и «Очистить корзину» (с подтверждением); автоочистка через 30 дней (SPEC 5.7).

**D-081 · 2026-11-23 · Закрытие формы с введёнными данными — вопрос «Не сохранять желание?»** (то же при редактировании — «Не сохранять изменения?»). Пустая форма закрывается без вопросов.

**D-082 · 2026-11-23 · Удаление списка:** подтверждение «Удалить список и N желаний?», желания уходят в корзину. Последний список удалить нельзя (пункт недоступен с пояснением). Если удалён список по умолчанию — по умолчанию становится первый из оставшихся. Если восстанавливают желание, чьего списка уже нет, — окно выбора списка, предвыбран список по умолчанию, можно поменять.

**D-083 · 2026-11-23 · Профиль:** имя и аватар берутся из Telegram или Google, имя можно изменить. Способы входа видны; подключение второго способа — этап 3, вместе с ботом («Подключить Telegram», D-085).

**D-084 · 2026-11-23 · Фото: выбрать можно только картинку** — JPG, PNG, WEBP, HEIC (снимки iPhone), до 20 МБ. В блоке фото — короткая подсказка: «JPG, PNG или HEIC до 20 МБ. Подойдёт скриншот». Фото меньше ~800 px по длинной стороне принимаем, но предупреждаем, что будет нечётко. Если файл всё же не тот или слишком большой — понятная ошибка. Лимит 20 МБ — рабочее значение: в Storage уходит сжатая копия ~800 px.

**D-085 · 2026-11-23 · Порядок этапов: совместные списки — этап 2, Telegram-бот — этап 3. Меняет D-034.** Итого: ядро → совместные списки → бот → публичные ссылки и брони → связанные карточки. Причина: автор и жена хотят как можно раньше вести общие списки; бот — удобство добавления, его можно подождать. Метки этапов в SPEC, BACKLOG, ROADMAP и OPEN_QUESTIONS переставлены. В более ранних записях журнала решений «этап 2» = бот, «этап 3» = совместные списки.

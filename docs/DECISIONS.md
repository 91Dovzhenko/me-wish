# Журнал решений

Формат: номер, дата, решение, причина. Новые решения — внизу. Отменённое решение не удаляем, а помечаем «Заменено D-xxx».

## Продукт

**D-001 · 2026-11-22 · Название — me:wish** (в технических именах `me-wish`). Продолжение линейки me:level.

**D-002 · 2026-11-22 · Ключевая фича — создание карточки по ссылке без предпросмотра.** Карточка создаётся сразу, правки потом. Причина: длина пути добавления — главная боль существующих сервисов.

**D-003 · 2026-11-22 · Несколько независимых списков, как доски Pinterest.** Отдельной сущности «Событие» нет: список под событие с датой и описанием. Причина: знакомая механика, меньше сущностей.

**D-004 · 2026-11-22 · Любое желание можно сохранить, даже только с названием.**

**D-005 · 2026-11-22 · Цены автоматически не обновляются.**

**D-006 · 2026-11-22 · Характеристики товара (размер, цвет, модель) — свободный комментарий, а не автоопределение.** Причина: автоопределение вариантов ненадёжно и усложняет добавление.

**D-007 · 2026-11-22 · Удаление карточки — в корзину на 30 дней. Архива карточек нет:** роль архива играют статусы «Куплено сам» / «Подарено». Архив есть только для списков.

**D-008 · 2026-11-22 · Приоритет — 1–5, свой в каждом списке.**

**D-009 · 2026-11-22 · Валюты RUB, USD, EUR.** Сумма списка — только по рублям, остальные показываются отдельно, без конвертации.

**D-010 · 2026-11-22 · Только сетка карточек**, без переключения на вид списка. Поиск и фильтры — не в MVP, есть сортировка и переключатель «Показывать завершённые».

## Доступ и роли

**D-011 · 2026-11-22 · Две роли: редактор и зритель.** Владелец и редактор объединены, у всех редакторов равные права, включая удаление списка. Причина: в совместных списках (пара, друзья) иерархия не нужна.

**D-012 · 2026-11-22 · Голосуют только редакторы.** Решение по карточке — единогласное, голос у каждого свой. Гости и зрители голоса не видят.

**D-013 · 2026-11-22 · Бронирование и голосование — независимые настройки списка.**

**D-014 · 2026-11-22 · Видимость списка: приватный или по ссылке.** Публичного профиля нет.

## Бронирование

**D-015 · 2026-11-22 · Бронь без регистрации; контакт необязателен.** Без контакта управлять бронью можно только с того же устройства (гостевой токен в браузере).

**D-016 · 2026-11-22 · Общая ссылка на список + персональная ссылка для управления своими бронями.** Причина: одну ссылку кидают в общий чат, персональная защищает чужие брони.

**D-017 · 2026-11-22 · Анонимность:** владелец списка задаёт «выбор дарителя / только анонимно / только открыто». Контакт дарителя не видит никто, кроме него самого.

**D-018 · 2026-11-22 · Факт брони виден всем, включая владельца, сразу.** Скрывать факт до праздника не нужно.

**D-019 · 2026-11-22 · Срока брони и автоснятия нет. Число броней у одного дарителя не ограничено.**

**D-020 · 2026-11-22 · «Подарено» отмечает владелец вручную;** дата события статусы автоматически не меняет. Причина: день рождения могут отмечать позже даты.

**D-021 · 2026-11-22 · Если владелец купил забронированное сам** — предупреждение, после подтверждения бронь снимается, а даритель получает уведомление.

**D-022 · 2026-11-22 · Владелец может открыть свою публичную ссылку и бронировать** — без искусственных ограничений.

**D-023 · 2026-11-22 · Уведомления дарителю в Telegram — через кнопку, которая открывает бота со стартовым токеном.** Причина: бот не может написать первым.

**D-024 · 2026-11-22 · Совместные подарки и сбор денег — не в первой версии** (бэклог).

## Связанные карточки

**D-025 · 2026-11-22 · Общие поля:** название, картинка, ссылка, описание, цена, статус. **Свои:** приоритет, комментарий. Общие поля меняет любой редактор.

**D-026 · 2026-11-22 · При удалении связанной карточки спрашиваем «из этого списка / везде».**

**D-027 · 2026-11-22 · Бронь синхронизируется во всех списках, имя автора — по настройкам списка, где сделана бронь.**

## Техника

**D-028 · 2026-11-22 · Стек:** React + TypeScript + Vite, Supabase (Postgres, Auth, Storage, Edge Functions), GitHub Pages. Причина: опыт владельца с этим стеком в me:level, бесплатные тарифы.

**D-029 · 2026-11-22 · Формат — PWA, основной интерфейс — веб.** Нативного приложения нет (аккаунт разработчика Apple из России сложен и платный). Telegram Mini App — дополнительный интерфейс позже.

**D-030 · 2026-11-22 · Вход: Telegram основной, Google дополнительный.** Email-вход не делаем.

**D-031 · 2026-11-22 · В меню «Поделиться» на iOS не встраиваемся** (Safari не поддерживает Web Share Target). Быстрая команда iOS — в бэклог. На Android share target — дешёвое дополнение на этапе 2.

**D-032 · 2026-11-22 · Картинки товаров копируются в Storage и сжимаются.** Причина: ссылки маркетплейсов могут перестать работать или блокировать хотлинк.

**D-033 · 2026-11-22 · 152-ФЗ сейчас не учитываем** — сервис для близкого окружения. Вернуться к вопросу перед публичным запуском.

**D-034 · 2026-11-22 · Порядок этапов:** ядро → бот → совместные списки → публичные ссылки и брони → связанные карточки. Причина: первыми продуктом пользуются автор с женой.

## Процесс

**D-035 · 2026-11-22 · Instagram не поддерживаем для автозаполнения.** Причина: сервер загружает ссылку без входа в аккаунт и почти ничего не получает.

**D-036 · 2026-11-22 · Цикл работы:** сверка → интервью → ТЗ на дизайн → дизайн в Artifacts → ТЗ для Claude Code → реализация → разбор отчёта. Продуктовая работа — в проекте Claude, код — в Claude Code, общая локальная папка. Подробно в `WORKFLOW.md`.

## Этап 0 — подготовка

**D-037 · 2026-11-22 · Адрес сайта — бесплатный `<логин>.github.io/me-wish`, свой домен подключим позже** (Q-04 решено). Причина: бесплатно, ничего не нужно покупать. Помнить: при смене домена надо будет перенастроить домен бота для входа через Telegram, а старые ссылки на списки перестанут работать.

**D-038 · 2026-11-22 · Репозиторий `me-wish` на GitHub — публичный.** Причина: на бесплатном тарифе GitHub Pages работает только с публичными репозиториями. Секреты в код не попадают.

**D-039 · 2026-11-22 · Ссылки в приложении чистые, без `#`** (например, `…/me-wish/l/abc`). Технически через приём с `404.html` на GitHub Pages. Причина: ссылки на списки будут рассылать гостям, они должны выглядеть аккуратно.

**D-040 · 2026-11-22 · Supabase — отдельный проект `me-wish` на бесплатном тарифе, регион Central EU (Frankfurt).** Причина: на аккаунте занят один проект из двух бесплатных; Франкфурт ближе всего к пользователям в России.

**D-041 · 2026-11-22 · Telegram-бот: имя «me:wish», адрес `@mewish_bot`.** Если адрес занят — `@me_wish_bot` или `@mewishlist_bot`.

**D-042 · 2026-11-22 · Тестовые ссылки для исследования разбора (3 Ozon, 3 WB, 3 Яндекс Маркет, 3 обычных магазина, 1 AliExpress) собирает владелец** из реальных желаний.

**D-043 · 2026-11-22 · Всё на GitHub владелец делает сам руками** (создание и публикация репозитория через GitHub Desktop, настройки Pages, переменные Actions, push) по пошаговым инструкциям из проекта Claude. Claude Code только готовит код и коммиты. Причина: владельцу так удобнее и понятнее.

**D-044 · 2026-11-22 · Настройки Supabase при создании проекта:** Data API включён; автоматическая выдача API-доступа к новым таблицам и автоматическое включение RLS — включены. Причина: RLS как страховка по умолчанию; без автоматической выдачи доступа запросы из приложения падали бы с ошибкой прав, если миграция забудет GRANT.

**D-045 · 2026-11-22 · Ключ Supabase для приложения — publishable key (`sb_publishable_…`)**, переменная по-прежнему называется `VITE_SUPABASE_ANON_KEY`. В GitHub Actions адрес и ключ хранятся как variables, а не secrets: они публичные и всё равно попадают в код сайта. Секретный ключ (secret / service_role) — только в секретах Supabase, никогда в GitHub и в браузере.

**Этап:** 0  **Связано:** ROADMAP «Этап 0», BACKLOG «Этап 0», DECISIONS D-028, D-029, D-037…D-040
**Дизайн:** не нужен (временная страница-заглушка, макетов нет)

## Контекст
Проект начинается с нуля. В папке `me-wish` пока только документация, `CLAUDE.md`, `README.md`, `.gitignore`. Git-репозиторий владелец создаёт сам через GitHub Desktop и публикует на GitHub до этой сессии (D-043). **Всё, что делается на GitHub (публикация, настройки Pages, переменные), владелец делает руками** — ты готовишь код и коммиты.
Задача: пустое приложение открывается по адресу в интернете, подключено к Supabase и устанавливается как PWA. Продуктовых функций в этой задаче нет.

Принятые решения:
- адрес сайта — `https://<логин>.github.io/me-wish/` (D-037), значит базовый путь приложения — `/me-wish/`;
- репозиторий публичный (D-038);
- ссылки чистые, без `#`: BrowserRouter + приём с `404.html` для GitHub Pages (D-039);
- Supabase — отдельный проект `me-wish`, Frankfurt (D-040). Владелец создаёт его перед этой сессией и даст тебе Project URL и публичный ключ (publishable / anon). Настройки доступа к данным при создании: Data API включён, «Grant API access to new tables automatically» и «Enable RLS on new tables automatically» включены (D-044) — RLS-политики всё равно пишутся явно в миграциях.

## Что сделать
1. **Git.** Репозиторий уже есть (ветка `main`). `git init` не делать. Если репозитория вдруг нет — остановись и скажи владельцу.
2. **Каркас фронтенда.** Vite + React + TypeScript + Tailwind CSS + React Router, ESLint + Prettier. Актуальные стабильные версии. Структура папок — как в `CLAUDE.md`.
3. **Маршрутизация.** BrowserRouter с `basename` `/me-wish/`. Приём с `404.html` (или аналог), чтобы прямой переход на любой адрес внутри приложения, например `/me-wish/l/test`, открывал приложение, а не 404 от GitHub. Для неизвестных адресов — простая страница «Страница не найдена» со ссылкой на главную. Выбранный способ описать в `docs/tech/routing.md`.
4. **Деплой.** GitHub Actions: сборка и публикация на GitHub Pages при пуше в `main`. Переменные Supabase для сборки берутся из GitHub (Settings → Secrets and variables → Actions). В отчёте перечисли точные имена переменных, тип (secret или variable) и откуда взять значение; пошаговую инструкцию по GitHub владельцу даст проект Claude.
5. **Supabase.**
   - Установить Supabase CLI (если его нет), `supabase init` → папка `supabase/` с `migrations/` и `functions/`.
   - Связать с облачным проектом (`supabase link`). Если нужен вход (`supabase login`) или пароль базы — попроси владельца и объясни, что нажать.
   - Клиент Supabase в `src/lib/supabase.ts`, переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (или publishable). Локально — в `.env` (не коммитить), шаблон — в `.env.example`.
   - Миграций и таблиц в этой задаче нет.
6. **Страница-заглушка** (главная, по-русски, удобная на 390px и на десктопе):
   - логотип-надпись «me:wish» и строка «Списки желаний — скоро здесь»;
   - индикатор связи с Supabase: «Supabase: подключено» (зелёный) / «Supabase: нет связи» (красный) — по реальному запросу к проекту, например к health-эндпоинту Auth;
   - мелким шрифтом внизу — дата и время сборки, чтобы владелец видел, что открыта свежая версия.
   - Цвета и шрифты — нейтральные временные, задать через CSS-переменные. Позже придёт дизайн; светлая и тёмная тема — DESIGN.md п. 8, здесь достаточно, чтобы заглушка нормально выглядела в обеих.
7. **PWA.**
   - Манифест: название «me:wish», короткое имя «me:wish», `lang: ru`, `display: standalone`, `start_url` и `scope` — `/me-wish/`, цвета темы — временные.
   - Временные иконки (простая надпись или буква на цветном фоне): 192, 512, maskable, `apple-touch-icon` 180×180. Мета-теги для iOS (добавление на главный экран).
   - Service worker с автообновлением, чтобы после нового деплоя у владельца не оставалась старая версия. Можно `vite-plugin-pwa`.
8. **README.md** — коротко: как запустить локально, как устроен деплой, какие переменные нужны.
9. **Коммит** с понятным сообщением на русском. Не пушить — владелец сделает Push через GitHub Desktop сам.

## Что НЕ делать
- Вход через Telegram или Google, таблицы, RLS, Edge Functions — это этап 1.
- Telegram-бота не трогать (владелец создаёт его в BotFather отдельно).
- Исследование разбора ссылок — отдельное ТЗ `002-parsing-research`.
- Не придумывать дизайн приложения сверх заглушки, не добавлять UI-библиотеки компонентов.
- Не пушить в GitHub самостоятельно, не создавать и не настраивать репозиторий, не использовать `gh` и API GitHub.

## Изменения в базе данных

## Как проверить (для владельца)
1. Открыть `https://<логин>.github.io/me-wish/` — видно «me:wish», зелёная надпись «Supabase: подключено», внизу сегодняшняя дата сборки.
2. В адресной строке дописать `l/test` и нажать Enter — открывается страница приложения «Страница не найдена» со ссылкой на главную, а не серая страница GitHub.
3. На iPhone: Safari → открыть адрес → «Поделиться» → «На экран Домой». Появляется иконка, по нажатию приложение открывается на весь экран.
4. На Mac в Chrome: значок установки справа в адресной строке → приложение появляется в Dock/Launchpad.

# 003-f — ТЗ для Claude Code: вход через Telegram

**Этап:** 1 (последнее из шести ТЗ, D-098)  **Связано:** SPEC §1.1–1.2, §1.4–1.5; DOMAIN §3 (User: `telegram_id`); DECISIONS D-041, D-083, D-091, D-099, D-109; CLAUDE.md (секреты, Edge Functions)
**Дизайн:** выгрузка `docs/design/stage1/` — `Mobile-Login`, `Desktop-Login`, `Mobile-Login-Loading`, `Mobile-Login-Error`, `Mobile-Profile`, `Desktop-Profile`.

## Контекст
Этап 1 готов, кроме входа через Telegram: кнопка «Войти через Telegram» на экране входа неактивна с меткой «скоро». Жена владельца будет входить именно через Telegram.

Вход через Google работает — Supabase Auth, PKCE (`docs/tech/stage1-foundation.md`). У Supabase нет встроенного провайдера Telegram, поэтому вход проверяется на сервере, в Edge Function (SPEC §1.2).

## Подготовка — делает владелец до запуска ТЗ
1. Бот создан в @BotFather (D-041, D-109), домен для входа задан командой `/setdomain` → `91dovzhenko.github.io`.
2. Токен бота сохранён в Supabase: Edge Functions → Secrets, имя `TELEGRAM_BOT_TOKEN`. **Токен никогда не попадает в код, GitHub, чат и браузер.**
3. Имя бота (например, `mewish_bot`) владелец сообщит, когда передаст ТЗ. Его и числовой id бота (часть токена до двоеточия — публичная) нужно положить в публичные переменные сборки:
   - локально — `.env`;
   - в GitHub Actions — variables, по образцу `VITE_SUPABASE_URL`.

   Пошаговую инструкцию для владельца, куда в GitHub добавить переменные, напиши в отчёте. Обнови `.env.example`.

## Что сделать
1. **Кнопка «Войти через Telegram» на экране входа** (`Mobile-Login`, `Desktop-Login`) становится активной.
   - Оформление — наша кнопка по макету, а не стандартный виджет Telegram, если это возможно. Например, через вход Telegram с переадресацией (`oauth.telegram.org/auth` с `bot_id`, `origin`, `return_to` — результат приходит обратно в адресе).
   - Если без стандартного виджета никак — используй его и объясни в отчёте почему.
   - Проверь работу на iPhone в Safari и в установленном приложении (standalone), а также на Mac.
2. **Проверка на сервере** — Edge Function, например `telegram-auth`:
   - проверяет подпись данных Telegram по токену бота (HMAC по алгоритму Telegram);
   - проверяет, что `auth_date` свежий (не старше нескольких минут);
   - находит или создаёт пользователя Supabase для этого `telegram_id` и выдаёт приложению обычную сессию Supabase. Дальше всё работает как при входе через Google: RLS, профиль, списки.

   Как именно выдавать сессию, реши сам (например, через Admin API и одноразовую ссылку или код). Условия: бесплатно, без внешних сервисов, секреты только в секретах Supabase, никаких ключей `service_role` в браузере. Запиши решение в `docs/tech/`.
3. **Первый вход через Telegram** работает как через Google, триггер первого входа уже есть:
   - создаётся профиль — имя из Telegram (имя и фамилия), аватар из Telegram, если есть;
   - создаётся список «Мои желания» и ставится списком по умолчанию;
   - в профиль записывается `telegram_id` (DOMAIN §3).

   Убедись, что триггер первого входа корректно берёт имя и аватар из данных Telegram.
4. **Состояния** — по макетам: «Входим…» (`Mobile-Login-Loading`), ошибка «Не получилось войти» с «Попробовать ещё раз» (`Mobile-Login-Error`). Ошибкой считаются: неверная подпись, устаревшие данные, отказ пользователя в Telegram.
5. **Профиль:** в «Способах входа» показывается «Telegram — вход выполнен» у тех, кто вошёл через Telegram (D-091). Кнопок «Подключить» нет.
6. **Метку «скоро»** у кнопки Telegram убрать.

## Важно про аккаунты
- Вход через Telegram и вход через Google — **разные аккаунты**, пока нет привязки второго способа входа (этап 3, D-083).
- Если владелец, у которого аккаунт через Google, войдёт через Telegram, у него появится второй, пустой аккаунт. Так и должно быть на этом этапе.
- Ничего не объединяй автоматически, но напиши об этом в отчёте понятными словами.

## Что НЕ делать
- Вебхук бота, приём сообщений и скриншотов, привязку чата, «Подключить Telegram» — этап 3.
- Объединение аккаунтов Google и Telegram.
- Вход по номеру телефона.

## Изменения в базе данных
- `profiles.telegram_id` (уникальный, может быть пустым), если ещё нет.
- Доработка триггера первого входа под данные Telegram, если нужна.
- RLS не ослаблять. Edge Function работает с минимально нужными правами.

## Критерии приёмки
- [ ] На iPhone (Safari и установленное приложение) и на Mac можно войти через Telegram: подтверждение в Telegram → «Входим…» → главная «первый вход» с «Моими желаниями».
- [ ] Повторный вход тем же Telegram открывает тот же аккаунт, второго пользователя не появляется.
- [ ] Поддельные или устаревшие данные входа отклоняются сервером (проверь запросами к функции, результат в отчёте).
- [ ] Токен бота есть только в секретах Supabase; в коде, сборке, GitHub и браузере его нет (проверь поиском по сборке).
- [ ] Имя и аватар из Telegram попадают в профиль; в «Способах входа» — Telegram.
- [ ] Вход через Google по-прежнему работает.
- [ ] Сборка, линтер чистые; ошибок в консоли нет.

## Как проверить (для владельца)
1. На iPhone жены откройте `https://91dovzhenko.github.io/me-wish/` в Safari и нажмите «Войти через Telegram».
2. Подтвердите вход в Telegram. Обычно приходит сообщение от Telegram или открывается окно подтверждения.
3. Мелькнёт «Входим…», откроется главная: её имя, пустые «Мои желания», «С чего начать».
4. Профиль → «Способы входа»: Telegram.
5. Выйдите и войдите снова — откроется тот же аккаунт.
6. На своём устройстве убедитесь, что вход через Google работает как раньше и данных жены вы не видите.

# 004-a — ТЗ для Claude Code: участники и приглашения

**Этап:** 2 (первое из двух ТЗ: 004-a участники и приглашения → 004-b как выглядят совместные списки)
**Связано:** SPEC §6.1–6.2a; DOMAIN §1, §3 (ListMember, Invite), §4; DECISIONS D-011, D-111, D-112…D-117, D-119; бриф `docs/design-briefs/004-shared-lists.md`; интервью `docs/interviews/004-shared-lists.md`
**Дизайн:** выгрузка **`docs/design/current/`** — новая, с кодами экранов. Как читать и таблица «код → файл» — `README.md` там же. **Если ТЗ и макет расходятся — делай по макету (D-101).**

## Контекст
Этап 1 готов. В базе уже есть `list_members` с ролями `editor` и `viewer`, и RLS устроена через участие: участники читают, редакторы меняют (`docs/tech/stage1-foundation.md`, `lists.md`, `wish-card.md`, `trash-profile.md`). Но добавить участника сейчас нельзя: клиент не может писать в `list_members`, приглашений нет.

Вход — Google или Telegram-бот по одноразовому коду (`docs/tech/` по 003-f2). Голосования нет (D-112).

Это ТЗ — **механика участия**: пригласить, принять, сменить роль, убрать, выйти, удалить у всех. Как совместные списки выглядят на главной, аватары «кто добавил», режим зрителя, корзина с «Удалила Олеся» — следующее ТЗ, 004-b.

## Что сделать

### 1. Приглашение (D-113)
1. **Меню «•••» списка:** «Редактировать», «Участники», «Удалить», «Выйти из списка» — по 2.18.
   - «Выйти из списка» видно, если у списка больше одного участника.
   - Для единственного участника «Удалить» работает как сейчас (последний список удалить нельзя — D-082).
2. **«Участники»** (шторка на телефоне, окно на компьютере — 2.21–2.22D):
   - участники: аватар, имя, роль, у себя пометка «вы»;
   - активные ссылки-приглашения;
   - если вы единственный участник — пустое состояние с «Пригласить» (2.21).
3. **«Пригласить»** (2.25, 2.26):
   - выбор роли «Редактор» или «Зритель»;
   - создаётся ссылка вида `https://91dovzhenko.github.io/me-wish/i/<токен>`;
   - кнопки «Скопировать ссылку» (тост «Ссылка скопирована») и «Поделиться» — системное меню `navigator.share`, если доступно;
   - подпись про 7 дней.
4. **Ссылка:**
   - многоразовая, действует 7 дней;
   - токен длинный и случайный, в базе только **хэш** (CLAUDE.md);
   - «Отозвать» в «Участниках» делает ссылку недействительной;
   - создавать и отзывать ссылки может любой редактор.

   Зрителю «Пригласить» недоступно (2.24).

### 2. Принять приглашение
5. **Адрес `/i/<токен>`:**
   - **Не вошёл** (1.5, 1.5D) — экран входа с карточкой приглашения. После входа (Google или Telegram-бот) пользователь **возвращается на этот же адрес** и видит шаг «Принять». Контекст приглашения не должен теряться при возврате из Google и при входе через бота — в том числе в установленном приложении на iPhone.
   - **Вошёл** (1.6, 1.6D) — карточка: обложка, название, кто приглашает (аватар, имя), роль, число желаний; «Принять» / «Не сейчас».
   - **После «Принять»** — экран списка и тост «Вы присоединились к «…»» (1.8).
   - **Ссылка устарела, отозвана или список удалён** (1.7, 1.7D) — «Приглашение больше не действует».
   - **Уже участник** или **это ваш список** — сразу открыть список. Повторное принятие роль не понижает.
6. Принятая ссылка остаётся действующей для других (многоразовая) до срока или отзыва.
7. **Данные карточки приглашения** — обложка, имя приглашающего, число желаний — до принятия отдаются через Edge Function или функцию базы только по действующему токену. Чужой список по токену целиком не открывается.

### 3. Управление участниками (D-116)
8. Любой редактор в «Участниках» может:
   - **сменить роль** другого участника (редактор ↔ зритель) — 2.23;
   - **убрать** участника — диалог «Убрать Олесю из списка?» (2.30).

   Себя редактор не понижает и не убирает — для этого есть «Выйти».
9. **«Выйти из списка»** — диалог 2.28.
   - Если вы последний редактор (зрители могут оставаться) — диалог 2.29 «Вы последний редактор — список удалится». После подтверждения список удаляется по правилам удаления (желания — в корзину, D-082).
   - Выйти из своего единственного списка нельзя: у пользователя всегда есть хотя бы один список, где он редактор (D-082). Подумай, как это показать: пункт неактивен с пояснением, как в 2.11.
10. **«Удалить» в совместном списке** — диалог 2.27 «Удалить список у всех участников?». Удаляет для всех. Желания — в корзину; кто и как их видит — по D-117, экран корзины доделается в 004-b.
11. **Список по умолчанию** (D-117). Если пользователь вышел или его убрали из списка, который был у него «по умолчанию», по умолчанию становится его первый оставшийся список, где он редактор.

### 4. Синхронизация
12. Изменения состава (принял, убрали, сменили роль, вышел, удалили список) приходят другим участникам без перезапуска — Realtime и обновление при возвращении, как в `docs/tech/sync.md`.
    - Если вас убрали из открытого списка — переход на главную и тост «Вас убрали из «…»».
    - Если список удалили — тост «Список «…» удалён».

## Что НЕ делать
- Разделы на главной, аватары участников на обложке и в шапке, мини-аватар «кто добавил», режим зрителя в интерфейсе, корзину с «Удалила Олеся», «Переместить» и выбор списка с совместными — 004-b.

  Пока совместный список показывается на главной как обычный. Зритель может видеть кнопки правки, но база не даст ему ничего изменить (RLS уже это обеспечивает — проверь).
- Голосование (D-112), уведомления, приглашения по почте, публичные ссылки для гостей (этап 4).

## Изменения в базе данных
- Таблица `invites`: `id, list_id, role, token_hash, created_by, created_at, expires_at, revoked_at` (DOMAIN §3), RLS. Через клиент редакторы списка видят и отзывают ссылки своего списка; создание и принятие — через функции.
- Функции (security definer, с проверками):
  - создать приглашение — только редактор, возвращает токен один раз;
  - посмотреть приглашение по токену — минимум данных для карточки;
  - принять приглашение — добавляет в `list_members` с ролью, не понижает существующую;
  - сменить роль, убрать участника — только редактор, не себя;
  - выйти из списка — с правилом последнего редактора и списка по умолчанию.
- Удаление совместного списка для всех — доработать `delete_list`, если нужно.
- Последний список пользователя: правило «у пользователя всегда есть хотя бы один список, где он редактор» должно учитывать совместные списки.
- **RLS-тесты на трёх пользователях** (владелец, редактор, зритель):
  - зритель не может менять список, желания, участников, создавать приглашения;
  - посторонний без принятия ничего не видит;
  - по устаревшему или отозванному токену нельзя вступить;
  - убранный участник теряет доступ сразу.

## Критерии приёмки
- [ ] Редактор создаёт ссылку с ролью, копирует или делится ею; ссылка видна в «Участниках», её можно отозвать.
- [ ] По ссылке: не вошедший входит (Google и Telegram-бот, в том числе в установленном приложении на iPhone) и попадает на «Принять»; вошедший сразу видит «Принять»; после принятия — список и тост.
- [ ] Устаревшая, отозванная ссылка или удалённый список — «Приглашение больше не действует»; уже участник — сразу список.
- [ ] Смена роли, «Убрать», «Выйти», «Вы последний редактор», «Удалить у всех» — по макетам и правилам выше.
- [ ] Изменения состава приходят другим участникам без перезапуска.
- [ ] Зритель через базу ничего не может изменить (проверено тестами), даже если видит кнопки.
- [ ] RLS-тесты на трёх пользователях проходят, старые тоже; токены приглашений в базе только в виде хэша.
- [ ] Сборка, линтер чистые; ошибок в консоли нет; 390 px без горизонтальной прокрутки.

## Как проверить (для владельца)
1. На Mac откройте «Для дома» (или создайте) → «•••» → «Участники» → «Пригласить» → «Редактор» → «Скопировать ссылку». Отправьте Олесе в Telegram.
2. Олеся открывает ссылку на iPhone → «Виталий приглашает вас в «Для дома»» → «Принять» → видит список и тост «Вы присоединились».
3. У вас в «Участниках» появилась Олеся. Добавьте желание в «Для дома» — у Олеси оно появится через пару секунд, и наоборот.
4. Смените Олесе роль на «Зритель», затем обратно на «Редактор».
5. Создайте вторую ссылку и отзовите её — по ней Олеся увидит «Приглашение больше не действует».
6. Олеся: «•••» → «Выйти из списка» → у неё список исчезает, у вас в «Участниках» её больше нет. Пригласите снова — для проверки 004-b список понадобится совместным.

# 003-a — ТЗ для Claude Code: основа интерфейса, база данных и вход через Google

**Этап:** 1 (первое из шести ТЗ: 003-a…f, D-098)  **Связано:** SPEC §1.1, §1.4–1.5, §2.1–2.2; DOMAIN §1–4, §6; DECISIONS D-046…D-048, D-050, D-052, D-055, D-066, D-074…D-076, D-086, D-091, D-093, D-095, D-097; бриф `docs/design-briefs/003-personal-wishlist.md`
**Дизайн:** утверждён (D-097). Выгрузка — `docs/design/stage1/`, начни с `README.md` там же. Оригинал холста: https://claude.ai/artifact/UmB9vPzs6WZYo6rNKBqpbY (из Claude Code не открывается, работай по выгрузке).

## Контекст
Каркас из 001 есть: Vite + React + TS + Tailwind 4, React Router с чистыми ссылками (`docs/tech/routing.md`), Supabase подключён, PWA, деплой на GitHub Pages `https://91dovzhenko.github.io/me-wish/`. Сейчас в `src/` заглушка и временные цвета.

Это ТЗ закладывает фундамент этапа 1:
- дизайн-систему по утверждённой спецификации;
- раскладку экранов для телефона и компьютера;
- всю схему базы этапа 1 с RLS;
- вход через Google;
- экран «Первый вход».

После него владелец может войти через Google и увидеть свою пустую главную (жена будет входить через Telegram — ТЗ 003-f). Остальное (списки, желания, корзина, профиль, вход через Telegram) — следующими ТЗ, их **не делай**.

## Подготовка — делает владелец до запуска ТЗ
Без этого вход через Google не заработает. Если к началу работы настройка не сделана, всё равно сделай код. Проверь то, что можно проверить без входа, и в отчёте напиши, что осталось проверить после настройки.
1. Google Cloud Console → новый проект `me-wish` → **OAuth consent screen**: тип External, имя «ME:WISH», почта владельца; доступы только `openid`, `email`, `profile`. Статус **In production** (для этих трёх доступов проверка Google не нужна). **Сделано иначе (D-099):** приложение оставлено в режиме Testing, почта владельца добавлена в Test users (для In production Google требует политику конфиденциальности, её пока нет). При входе Google показывает «Google hasn't verified this app» → «Continue» — это ожидаемо.
2. **Credentials → Create credentials → OAuth client ID**, тип Web application:
   - Authorized JavaScript origins: `https://91dovzhenko.github.io` и `http://localhost:5173`;
   - Authorized redirect URIs: `https://ldpxoyqpxesypgxjakxf.supabase.co/auth/v1/callback`;
   - сохранить Client ID и Client secret.
3. Supabase → **Authentication → Sign In / Providers → Google**: включить, вставить Client ID и Client secret, сохранить.
4. Supabase → **Authentication → URL Configuration**:
   - Site URL: `https://91dovzhenko.github.io/me-wish/`;
   - Redirect URLs: добавить `https://91dovzhenko.github.io/me-wish/**` и `http://localhost:5173/me-wish/**`.

Всё бесплатно. Client secret хранится только в Supabase, в код и GitHub он не попадает.

## Что сделать

### 1. Дизайн-система
1. **Цвета, отступы, скругления, тени** — из `Spec-Foundations.dc.html`, как CSS-переменные (`--bg`, `--surface`, `--text`, `--text-2`, `--border`, `--divider`, `--accent`, `--accent-2`, `--accent-2-soft`, `--accent-2-text`, `--heart`, `--danger` и т. д.), проброшенные в Tailwind. Сюда же 8 цветов списков (фон + цвет иконки) из `ListIcon.dc.html`.
2. **Временные цвета и тёмную тему из 001 убрать.** На этапе 1 только светлая тема (D-055), но все цвета остаются переменными.
3. **Шрифты** Unbounded (логотип, заголовки экранов, крупные цифры) и Onest (весь остальной текст), с кириллицей. Подключи через Google Fonts или локально: выбери сам и запиши в `docs/tech/`.
4. **Базовые компоненты — только те, что нужны в этом ТЗ:**
   - логотип ME:WISH (знак + надпись, D-076);
   - кнопки: лаймовая главная, тёмная, светлая с рамкой, текстовая ссылка;
   - аватар с инициалами и с фото;
   - иконка списка на цвете (`ListIcon`; набор из 30 иконок — тот же, что на холсте; если готовой библиотеки с ними нет, перенеси SVG из выгрузки);
   - обложка списка: пустая с иконкой и с меткой даты (`Cover`);
   - скелетоны.

   Остальные компоненты из спецификации (поля, выпадающие списки, тосты, диалоги, карточки желаний, календарь) — в следующих ТЗ, по мере надобности.

### 2. Раскладка
5. **Телефон (до 1023 px)** — как `Main.dc.html` / `Mobile-FirstRun.dc.html`:
   - шапка: логотип слева, аватар справа;
   - плавающая круглая лаймовая «+» внизу справа;
   - нижней панели вкладок нет.
6. **Компьютер (от 1024 px)** — как `Desktop-Home.dc.html` / `Desktop-FirstRun.dc.html` и `Sidebar.dc.html`, вариант Б (D-093):
   - контент лежит прямо на светло-сером фоне, белой панели под ним нет;
   - боковое меню на белой скруглённой подложке: логотип, «Главная», «Мои списки» (иконка, название, число желаний), «+ Новый список», внизу профиль (аватар + имя);
   - активный пункт меню лаймовый, при наведении — серая подсветка;
   - если списков много, прокручивается только средняя часть меню (`Desktop-Home-ManyLists`).
7. **Сначала мобильная версия.** На ширине 390 px ничего не обрезается и не переносится там, где на макете одна строка.

### 3. База данных (миграции в `supabase/migrations/`)
8. Таблицы этапа 1 по DOMAIN §3 (в DOMAIN поля этапа 1 уже уточнены):
   - `profiles`: `id` = `auth.users.id`, `display_name`, `avatar_url`, `avatar_path`, `default_list_id`, `created_at`;
   - `lists`: `id`, `title`, `description`, `event_date`, `icon`, `color`, `cover_mode` (`collage` | `icon`, по умолчанию `collage`), `created_by`, `created_at`, `updated_at`;
   - `list_members`: `list_id`, `user_id`, `role` (`editor` | `viewer`), `added_at`;
   - `wishes`: `id`, `title`, `description`, `image_path`, `source_url`, `price` (целые рубли, D-072), `status` (`active` | `booked` | `purchased` | `gifted`), `completed_at`, `created_by`, `created_at`, `updated_at`;
   - `list_items`: `id`, `list_id`, `wish_id`, `priority` (1–5, по умолчанию 3), `position`, `added_by`, `added_at`, `deleted_at`.

   Связь желание ↔ список — многие ко многим через `list_items` с первого дня (DOMAIN §1). Поля будущих этапов (голосование, видимость, брони, архив) сейчас **не добавляй**.
9. **RLS на всех таблицах** (права — DOMAIN §4):
   - пользователь видит и меняет только списки, где он участник; зритель — только читает;
   - `list_items` и `wishes` доступны через участие в списке;
   - `profiles`: свой профиль — читать и менять; чужие — только `display_name` и аватар тех, с кем есть общий список (на этапе 1 общих списков нет, но правило заложи);
   - создатель списка автоматически становится редактором.
10. **При первом входе (триггер на новом пользователе Auth):**
    - создать профиль: имя и аватар — из данных Google;
    - создать список «Мои желания» (иконка — сердце, цвет — лавандовый, как на макете);
    - сделать пользователя редактором этого списка;
    - записать этот список в `default_list_id` (D-048).
11. **Дашборд:** функция или представление для сводки главной (D-050):
    - «Активные» — количество и сумма: статус `active` / `booked`, не в корзине;
    - «Исполнено в <текущем году>» — количество и сумма: `purchased` / `gifted` с `completed_at` в текущем календарном году.

    Сумма — по `price`, пустые цены не считаются.

### 4. Вход
12. **Экран входа** — `Mobile-Login.dc.html` и `Desktop-Login.dc.html`. Наклонённые карточки товаров на экране — декоративные. Фото для них сделай нейтральными: свои простые иллюстрации или заглушки в стиле `Photo.dc.html`. Скриншоты с маркетплейсов не бери.
13. **«Войти через Google»** — Supabase Auth, OAuth Google. После входа пользователь возвращается в приложение на `/me-wish/`, с учётом базового пути GitHub Pages.
14. **«Войти через Telegram»** на экране есть, но на этом ТЗ неактивна: подпись «скоро» или неактивное состояние. Вход через Telegram — ТЗ 003-f.
15. **Состояния:**
    - «Входим…» (`Mobile-Login-Loading`) — пока идёт возврат из Google и создаётся профиль;
    - ошибка входа (`Mobile-Login-Error`) — «Попробовать ещё раз».
16. Пока не вошёл — все адреса, кроме экрана входа, ведут на вход. После входа экран входа ведёт на главную.

### 5. Главная — только состояние «первый вход» и загрузка
17. **Главная по данным из базы:**
    - сводка — две строки на телефоне (D-086) и одна строка на компьютере, у «Исполнено» лаймовая галочка;
    - «Мои списки»: обложки списков пользователя (сейчас это будет один пустой «Мои желания» с иконкой на его цвете, «Пока пусто»);
    - блок «С чего начать» из `Mobile-FirstRun` / `Desktop-FirstRun`.
18. **Загрузка:** скелетоны (`Mobile-Home-Loading`, `Desktop-Home-Loading`).
19. **Неактивные пока кнопки.** «+» (плавающая), «Добавить желание», «Добавить первое желание», «+ Новый список» и нажатие на обложку списка видны как на макете, но на этом ТЗ ничего не делают (неактивное состояние или без реакции). Они оживут в 003-b и 003-c.
20. **Выход:**
    - на компьютере — меню профиля внизу бокового меню (`Desktop-ProfileMenu`), из пунктов работает только «Выйти»;
    - на телефоне — нажатие на аватар открывает экран «Профиль», в нём пока только имя, аватар и «Выйти». Остальные блоки профиля — в 003-e.
21. **«Страница не найдена»** — по макетам `Mobile-NotFound` / `Desktop-NotFound` (маршрут `*` уже есть, нужно оформить).

## Критерии приёмки
- [ ] Вход через Google работает на опубликованном сайте и локально; после первого входа в базе есть профиль, список «Мои желания», участие и `default_list_id`.
- [ ] Главная после первого входа совпадает с `Mobile-FirstRun` (390 px) и `Desktop-FirstRun` (1440 px): шапка/боковое меню, сводка с нулями, пустая обложка «Мои желания», «С чего начать».
- [ ] Цвета, шрифты, скругления, отступы — по `Spec-Foundations`; тёмной темы нет.
- [ ] Компьютер — вариант Б: серый фон, белое скруглённое боковое меню, активный пункт лаймовый.
- [ ] Экран входа, «Входим…», ошибка входа, загрузка главной и «Страница не найдена» — по макетам.
- [ ] «Выйти» работает на телефоне и компьютере; без входа главная недоступна.
- [ ] RLS проверены на двух пользователях: второй не видит и не может изменить списки, желания и профиль первого (проверка запросами от имени двух пользователей; как проверял — в отчёте).
- [ ] Сборка без ошибок, в консоли браузера ошибок нет, на 390 px нет горизонтальной прокрутки.

## Как проверить (для владельца)
1. Откройте `https://91dovzhenko.github.io/me-wish/` на iPhone. Должен быть экран входа: две карточки, ME:WISH, «Все желания — в одном месте», чёрная кнопка Telegram (неактивна, «скоро») и белая Google.
2. Нажмите «Войти через Google» и выберите свой аккаунт. Мелькнёт «Входим…», затем главная: сводка «Активные 0 · 0 ₽» и «Исполнено в 2026: 0 · 0 ₽», обложка «Мои желания — Пока пусто», блок «С чего начать», лаймовый «+».
3. Нажмите на аватар → «Выйти» → снова экран входа.
4. Откройте сайт на Mac. Слева белое меню: «Главная» лаймовая, «Мои желания 0», «+ Новый список», внизу ваше имя. Справа на сером фоне сводка и обложка.
5. Изоляцию данных между пользователями проверяет Claude Code (RLS, два тестовых пользователя) — результат будет в отчёте.
6. Откройте `…/me-wish/abc` — оформленная «Страница не найдена» с кнопкой «На главную».

# 003-f2 — ТЗ для Claude Code: вход через Telegram-бота

**Этап:** 1 (доработка 003-f)  **Связано:** ТЗ `docs/tasks/003-f-telegram-login.md`, отчёт `docs/reports/003-f-telegram-login.md`; SPEC §1.2; DECISIONS D-109, D-110, D-111; CLAUDE.md (секреты, Edge Functions, гостевые токены — только хэш)
**Дизайн:** `Mobile-Login`, `Desktop-Login`, `Mobile-Login-Loading`, `Mobile-Login-Error`. Новых экранов нет, текст ожидания — ниже.

## Контекст
В 003-f вход через Telegram сделан через страницу Telegram с переадресацией (`oauth.telegram.org`). Владелец проверил на iPhone жены: и в установленном приложении (с экрана «Домой»), и после добавления переменных в GitHub нажатие на кнопку бесконечно показывает «Входим…». Результат входа не возвращается в приложение: установленное приложение на iOS живёт отдельно от Safari.

**Решение (D-111): вход через бота по одноразовому коду.** Вход через страницу Telegram убираем. Остаётся один способ, одинаковый для Safari, установленного приложения и Mac.

## Как должно работать
1. **Нажатие «Войти через Telegram».** Приложение просит сервер (Edge Function) создать запрос на вход. Сервер создаёт:
   - одноразовый **код** — короткий, случайный, его увидит бот;
   - **секрет устройства** — длинный, случайный, остаётся только в этом браузере.

   В базе хранится только хэш секрета (как с гостевыми токенами, CLAUDE.md). Запрос живёт 10 минут, используется один раз.
2. **Приложение открывает** `https://t.me/me_wish_bot?start=login_<код>`. На iPhone и Mac это открывает приложение Telegram с ботом. На экране входа — состояние ожидания по образцу `Mobile-Login-Loading`:
   - текст «Подтвердите вход в Telegram и вернитесь сюда»;
   - кнопка «Открыть Telegram ещё раз»;
   - кнопка «Отмена».
3. **Пользователь нажимает «Start» в боте.** Telegram присылает сообщение на вебхук (Edge Function, например `telegram-webhook`). Функция:
   - проверяет, что запрос пришёл от Telegram: секретный заголовок `X-Telegram-Bot-Api-Secret-Token`, заданный при `setWebhook`, хранится в секретах Supabase;
   - находит запрос на вход по коду и проверяет срок;
   - привязывает к нему `telegram_id`, имя, фамилию и username пользователя Telegram;
   - отвечает в чате: «Готово! Вернитесь в ME:WISH — вход выполнится сам.» Кнопку-ссылку на сайт не добавляй: на iPhone она откроет Safari, а не установленное приложение.

   Если код устарел или уже использован — бот отвечает «Ссылка для входа устарела. Нажмите «Войти через Telegram» в ME:WISH ещё раз».
4. **Приложение ждёт подтверждения.** Опрос сервера раз в 1–2 секунды или Realtime, а также проверка при возвращении в приложение. Как только запрос подтверждён, приложение обменивает **код + секрет устройства** на обычную сессию Supabase. Дальше — как в 003-f: найти или создать пользователя по `telegram_id`, профиль, «Мои желания».

   Без секрета устройства войти по коду нельзя: тот, кто увидит код, не сможет им воспользоваться.
5. **Ошибки:**
   - через 10 минут ожидания — «Не получилось войти» + «Попробовать ещё раз» (`Mobile-Login-Error`);
   - «Отмена» возвращает экран входа.
6. **Аватар из Telegram.** Если возможно бесплатно и без лишней сложности — получи фото профиля через Bot API (`getUserProfilePhotos` + `getFile`) и сохрани в бакет аватаров, как свой аватар. Если сложно — без аватара, инициалы. Решение — в отчёте.

## Что сделать
1. Таблица (или другое хранилище) запросов на вход:
   - поля: код, хэш секрета устройства, срок, статус, данные Telegram после подтверждения;
   - клиенту напрямую недоступна (RLS без политик для клиента);
   - работа только через Edge Functions;
   - старые запросы чистятся (можно в ночной уборке из 003-e).
2. Edge Functions:
   - создание запроса на вход;
   - вебхук бота;
   - проверка статуса и обмен кода на сессию — можно доработать `telegram-auth` из 003-f.

   Вебхук без проверки JWT, но с проверкой секретного заголовка Telegram.
3. **Регистрация вебхука** (`setWebhook` с `secret_token`, `allowed_updates: ["message"]`). Сделай одноразовой функцией или скриптом, токен бери из секретов Supabase. Опиши в отчёте, как перерегистрировать.
4. **Экран входа:** новый поток и состояние ожидания. Убери вход через `oauth.telegram.org` и связанный с ним код.
5. **Переменные:** `VITE_TELEGRAM_BOT_NAME` нужна для ссылки `t.me/...`. Если `VITE_TELEGRAM_BOT_ID` больше не нужна — напиши владельцу, что её можно удалить из GitHub.
6. **Бот на другие сообщения** (не `/start login_…`) отвечает коротко: «Это бот для входа в ME:WISH. Добавление желаний через бота появится позже.»

## Что НЕ делать
- Добавление желаний через бота, привязку чата к аккаунту Google, «Подключить Telegram» — это этап 3.
- Объединение аккаунтов Google и Telegram.
- Хранение кода или секрета в открытом виде, токена бота — где-либо кроме секретов Supabase.

## Изменения в базе данных
- Таблица запросов на вход (RLS включена, политик для клиента нет).
- Уборка старых запросов.

## Критерии приёмки
- [ ] На iPhone в **установленном приложении** (с экрана «Домой»): «Войти через Telegram» → открылся Telegram с ботом → «Start» → «Готово!» → вернулись в приложение → вошли без повторных действий.
- [ ] То же в обычном Safari на iPhone и в браузере на Mac (на Mac — с Telegram Desktop или веб-версией).
- [ ] Повторный вход тем же Telegram открывает тот же аккаунт.
- [ ] Код без секрета устройства не даёт сессию; устаревший и повторно использованный код отклоняется; запросы на вебхук без секретного заголовка отклоняются (проверь запросами, результат в отчёте).
- [ ] Токен бота и секрет вебхука — только в секретах Supabase; в коде, сборке и git их нет.
- [ ] Вход через Google по-прежнему работает.
- [ ] Сборка, линтер чистые; RLS-тесты проходят.

## Как проверить (для владельца)
1. На iPhone Олеси откройте ME:WISH с экрана «Домой» (если открыто — закройте полностью и откройте заново).
2. «Войти через Telegram» — откроется Telegram с ботом ME:WISH. Нажмите «Start».
3. Бот ответит «Готово! Вернитесь в ME:WISH…». Переключитесь обратно в ME:WISH — через пару секунд откроется главная.
4. Профиль → «Способы входа»: Telegram. Выйдите и войдите снова — тот же аккаунт.

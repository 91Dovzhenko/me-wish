# Открытая карточка, сортировка, «Исполнено» (ТЗ 003-d)

## Адрес карточки
- `/l/<list_id>/w/<list_item_id>` — маршрут `/l/:listId/*` в `src/App.tsx`, разбор хвоста в `ListPage`. Любой другой хвост — «Страница не найдена».
- В адресе id **появления** (`list_items.id`), а не желания: он не меняется при переносе и однозначно задаёт «желание в этом списке».
- Открыли из сетки — в истории есть запись, закрытие = «назад» (кнопка «Назад» браузера тоже закрывает). Открыли по ссылке — закрытие заменяет адрес на `/l/<list_id>`.
- «Не найдено»: желания нет среди доступных (чужое, в корзине, несуществующее) или оно в другом списке. Если открытую карточку удалили на другом устройстве — она просто закрывается.
- Прямые ссылки на GitHub Pages работают тем же приёмом с `404.html` (`docs/tech/routing.md`).

## Компоненты
- `src/features/wishes/WishSheet.tsx` — карточка: телефон — шторка (без свайпа, D-106), компьютер — окно 940 px. Приоритет (выбор из 5), статус (выпадающий список), «Ещё»/«Свернуть» у описания (видно, только если текст не влез в 4 строки), меню «•••», окно «Переместить», форма редактирования.
- Esc: сначала закрывает меню/выбор, потом карточку; при открытой форме Esc обрабатывает форма.
- Редактирование — та же `WishForm` (`mode="edit"`, `initial`). Смена списка в форме = перенос (карточка закрывается, тост «Перемещено в «…»»).
- `src/features/wishes/sort.ts` — 5 сортировок, «Без цены» в конце, при равенстве — приоритет, затем новые. Выбор хранится в `localStorage` (`me-wish:sort:<list_id>`); «По приоритету» — значение по умолчанию, ключ удаляется. «Исполненные» — в памяти экрана (после перезагрузки снова показаны).

## База (`supabase/migrations/20261126100000_wish_card.sql`)
Все функции — **security invoker**, т. е. действуют обычные политики RLS.
- `update_wish(p_item_id, p_list_id, p_title, p_price, p_source_url, p_description, p_priority, p_image_path)` — поля желания + приоритет и список появления одной транзакцией. Проверки как в `add_wish`. Нет прав / в корзине — `P0002 not_found`; перенос в чужой или удалённый список — `42501`.
- `trash_list_item(p_item_id)` / `restore_list_item(p_item_id)` — в корзину и обратно, дата по часам сервера. Вернуть в удалённый за это время список нельзя (политика `is_list_alive`).
- Приоритет (`list_items.priority`), статус (`wishes.status`) и «Переместить» (`list_items.list_id`) — обычные update; приложение просит `select('id')` и считает «0 строк» ошибкой.
- «Удалено · Отменить»: желание сразу пропадает с экрана, запрос `trash_list_item` уходит сразу. «Отменить» дожидается окончания удаления и вызывает `restore_list_item` (иначе возврат мог бы прийти раньше удаления).

## Проверка экранов без Google
Локальная заглушка Supabase (node-скрипт, не в репозитории) + `vite --mode mock` с `.env.mock.local` (`VITE_SUPABASE_URL=http://localhost:54399`, файл не коммитится) + тестовая сессия в `localStorage` (`sb-localhost-auth-token`). Realtime заглушка не умеет — в консоли ошибки WebSocket, это ожидаемо.

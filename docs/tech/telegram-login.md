# Вход через Telegram-бота (ТЗ 003-f2, D-111)

С 003-f2 вход через Telegram — **через бота по одноразовому коду**. Вход через страницу Telegram (`oauth.telegram.org` с переадресацией, ТЗ 003-f) убран: на iPhone в установленном приложении результат не возвращался в приложение.

Файлы:
- миграции `supabase/migrations/20261128100000_telegram_login.sql` (`profiles.telegram_id`) и `20261129100000_telegram_bot_login.sql` (запросы на вход);
- Edge Functions `supabase/functions/telegram-auth` и `supabase/functions/telegram-webhook`;
- клиент `src/auth/telegram.ts`, `src/auth/AuthProvider.tsx`, `src/pages/LoginPage.tsx`;
- тесты `supabase/tests/rls_003f_telegram.sql`, `rls_003f2_bot_login.sql`.

## Поток
1. **Экран входа заранее** просит `telegram-auth` `{action:'start'}` создать запрос.
   - Сервер создаёт **код** — 12 знаков, ~70 бит; его увидит бот.
   - И **секрет устройства** — 32 случайных байта (64 hex); он остаётся только в браузере.
   - В таблицу `telegram_login_requests` пишутся код и **sha256 секрета**. Запрос живёт 10 минут.
   - Заранее — потому что iPhone открывает Telegram только прямо из обработчика нажатия, без ожидания сети. Если до конца срока заготовки меньше 2 минут, создаётся новая.
2. **Нажатие «Войти через Telegram»** сразу открывает бота:
   - iPhone/iPad — `tg://resolve?domain=me_wish_bot&start=login_<код>`. Открывается приложение Telegram, а ME:WISH остаётся на месте — в Safari и в установленном приложении.
   - Компьютер — `https://t.me/me_wish_bot?start=login_<код>` в новой вкладке (оттуда Telegram Desktop или веб-версия). Если браузер заблокировал вкладку — переход в этой же.

   Запрос сохраняется в `localStorage` (`me-wish:tg-login`). Если iOS выгрузит приложение или вкладка уйдёт на t.me, после возвращения ожидание продолжится.
3. Экран ожидания: «Подтвердите вход в Telegram и вернитесь сюда», «Открыть Telegram ещё раз», «Отмена».
4. **Пользователь жмёт «Start».** Telegram присылает `/start login_<код>` на вебхук `telegram-webhook`.
   - Вебхук проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.
   - Подтверждает запрос, только если он `pending` и не истёк, один раз. К запросу привязываются `telegram_id`, имя, фамилия и username.
   - Отвечает в чате «Готово! Вернитесь в ME:WISH — вход выполнится сам.» Если код устарел или уже использован — «Ссылка для входа устарела…». На любые другие сообщения — «Это бот для входа в ME:WISH…». Кнопки-ссылки на сайт нет: на iPhone она открыла бы Safari, а не установленное приложение.
5. **Приложение опрашивает** `telegram-auth` `{action:'poll', code, secret}` раз в 1,5 с, пока экран виден, и сразу при возвращении в приложение (`visibilitychange`, `focus`, `pageshow`). Ответы:
   - `pending`;
   - `expired` — истёк срок или уже использован;
   - 404 — нет такого кода или секрет не тот; ответ одинаковый, чтобы не подсказывать, какие коды есть;
   - `ok` + `token_hash` — запрос подтверждён. Сервер переводит его в `used` атомарно (update `where status='confirmed'`), поэтому второй опрос получит `expired`.
6. На `ok` сервер находит или создаёт пользователя (как в 003-f):
   - аккаунт Telegram — тот, у профиля которого этот `telegram_id`, с почтой `telegram-<id>@me-wish.invalid`;
   - новый пользователь создаётся через Admin API, `telegram_id` записывается в профиль, профиль и «Мои желания» создаёт триггер первого входа;
   - одноразовый токен — `generateLink({type:'magiclink'})` → `hashed_token`.

   Браузер вызывает `supabase.auth.verifyOtp({ token_hash, type: 'magiclink' })` и получает обычную сессию.
7. Через 10 минут без подтверждения — «Не получилось войти» и «Попробовать ещё раз». «Отмена» стирает запрос и возвращает экран входа.

## Безопасность
- **Код без секрета бесполезен.** Тот, кто увидел код (например, в чате с ботом), может только подтвердить чужой запрос своим Telegram, но войти по нему не сможет — сессию получит устройство с секретом. В базе только хэш секрета.
- Запрос: 10 минут, подтверждается один раз (`pending` → `confirmed`), обменивается один раз (`confirmed` → `used`). `token_hash` тоже одноразовый.
- **Вебхук** принимает обновления только с секретным заголовком (сравнение без утечки по времени). Остальные — 403. Обрабатываются только личные сообщения от людей. На мусор вебхук отвечает 200, чтобы Telegram не повторял.
- **Таблица `telegram_login_requests`**: RLS включена, политик нет, права у `anon` и `authenticated` убраны. Работает только service role внутри Edge Functions.
- `telegram_id` в профиле ставит только сервер: клиент может менять в профиле только имя, аватар и список по умолчанию (003-f). Почте одной не доверяем: если служебную почту заняла чужая регистрация, вход не выдаётся.
- Создавать запросы может кто угодно (до входа). Это только строки в таблице; ночная уборка удаляет запросы старше суток.

## Аватар из Telegram
При первом входе сервер берёт фото профиля через Bot API (`getUserProfilePhotos` → `getFile`):
- размер — ближайший к 400 px из тех, что даёт Telegram (обычно 160/320/640), JPEG;
- сохраняется в бакет `avatars` как своё фото (`profiles.avatar_path`);
- бесплатно, без новых зависимостей; ссылка на файл с токеном используется только на сервере;
- нет фото или оно скрыто настройками приватности Telegram — инициалы;
- при повторных входах фото не обновляется — его можно сменить в профиле.

## Секреты и переменные
| Что | Где |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Supabase → Edge Functions → Secrets (положил владелец) |
| `TELEGRAM_WEBHOOK_SECRET` | Supabase → Edge Functions → Secrets (задал Claude Code, 64 hex; значение нигде не сохранено) |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | Supabase передаёт функциям сам |
| `VITE_TELEGRAM_BOT_NAME` = `me_wish_bot` | `.env` локально; GitHub → Actions variables (публичное) |

`VITE_TELEGRAM_BOT_ID` больше не нужна.

## Регистрация вебхука
Вебхук зарегистрирован: `https://ldpxoyqpxesypgxjakxf.supabase.co/functions/v1/telegram-webhook`, `allowed_updates: ["message"]`.

**Перерегистрировать** (сменился секрет, токен бота или адрес проекта): задать новый секрет и вызвать функцию с ним — она сама вызовет `setWebhook` с токеном из секретов и вернёт `getWebhookInfo`.

```bash
S=$(openssl rand -hex 32)
supabase secrets set TELEGRAM_WEBHOOK_SECRET=$S
curl -s -X POST -H "x-telegram-setup: $S" https://ldpxoyqpxesypgxjakxf.supabase.co/functions/v1/telegram-webhook
```

Подождать ~10 секунд между командами, пока функция подхватит новый секрет. В ответе `"Webhook was set"` и `url` вебхука. Без верного секрета — 403.

## Уборка
`purge_login_requests()` — `pg_cron` `me-wish-purge-login-requests` в 03:30 UTC удаляет запросы старше суток.

## Как проверено (запросами к облачным функциям)
| Проверка | Результат |
|---|---|
| Вебхук без заголовка / с чужим секретом / setup с чужим секретом | 403 / 403 / 403 |
| `start` | код 12 знаков, секрет 64 hex |
| Опрос до «Start» | `pending` |
| Код без секрета | 400 |
| Код с чужим секретом (до и после «Start») | 404 |
| Вебхук: другое сообщение | 200, ответ-подсказка |
| Вебхук: `/start login_<код>` | 200, запрос подтверждён (`telegram_id`, имя) |
| Опрос с секретом | `ok` + `token_hash` → `/auth/v1/verify` дал сессию |
| Повторный опрос того же кода | `expired` (использован) |
| Повторное использование `token_hash` | 400 |
| Второй вход тем же Telegram | **тот же пользователь** |
| Код с истёкшим сроком: бот не подтвердил, опрос | `expired` (запрос остался `pending`) |
| Таблица через REST с публичным ключом | 42501 permission denied |
| Профиль после первого входа | «Олеся Тест», `telegram_id`, по умолчанию «Мои желания» |

Тестовый Telegram id 1 (у него нет доступного фото — аватар не сохранился, как и должно быть без фото). Тестовые пользователь и запросы после проверки удалены. Для проверки вебхука его секрет был временно задан заново и после проверки нигде не сохранён.

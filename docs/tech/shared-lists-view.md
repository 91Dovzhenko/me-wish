# Как выглядят совместные списки (ТЗ 004-b)

Миграция `supabase/migrations/20261201100000_shared_view.sql`, тест `supabase/tests/rls_004b_shared_view.sql` (16 проверок).

## Раздел списка (D-114, D-123)
Считается в браузере из общего снимка (`AppData` → `sectionOf()`), поле `ListSummary.section`:
- `viewer` — моя роль «зритель» → «Со мной поделились»;
- `shared` — я редактор и среди участников есть ещё хоть один редактор → «Совместные»;
- `mine` — иначе (я единственный редактор; зрители могут быть) → «Мои списки».

Пустые разделы скрыты. Состав приходит Realtime по `list_members` (004-a), поэтому список переезжает между разделами без перезапуска. Сводка главной (`dashboard`) считает только списки, где я редактор (D-117).

## Данные
- Участники с ролями, именами и аватарами — из 004-a (`list_members` + `profiles_public`).
- Кто добавил: `list_items.added_by` грузится вместе с желаниями. Имя и аватар берутся из того же `profiles_public` (`WishItem.addedBy`). Отдельного запроса на карточку нет. Если добавивший больше не делит со мной ни одного списка, имя неизвестно — «Участник».
- `components/AvatarStack` — до 3 аватаров с наложением 30 % и «+N». Используется на обложке, в шапке списка, в боковом меню и в выборе списка.

## Кто удалил — `list_items.deleted_by`
- Ставит триггер `list_items_track_deleted` по смене `deleted_at`:
  - поставили — `auth.uid()` (в функциях security definer это тоже вызывающий: `trash_list_item`, `delete_list`, `leave_list` последним редактором);
  - сняли — `null`;
  - без смены `deleted_at` значение не меняется.
- Клиент подменить не может (проверено тестом), как и `added_by`. Автоочистка (`auth.uid()` пустой) прежнее значение не трогает.
- `trash_items()` переписан:
  - только списки, где я **редактор** (зритель корзину чужого списка не видит);
  - `deleted_by`, имя и аватар удалившего — только если это не я;
  - `list_shared` — в списке есть другие участники (для предупреждения в «Очистить корзину»).
- `empty_trash` (без изменений) удаляет навсегда всё, что выбрано и где я редактор, — в том числе удалённое другими (D-122).
  - Фото чужих желаний лежат в папке их автора, браузер их удалить не может (политика Storage). Такие файлы подберёт ночная уборка `storage-cleanup` (003-e).

## Зритель в интерфейсе
- Список (2.19): метка «Вы зритель — только просмотр», нет «+» и «Добавить желание», в пустом списке — без «Добавить первое желание».
- Карточка (4.13): цена, приоритет и статус — текстом; нет «•••», «+ Добавить фото», «+ Указать цену»; «Перейти в магазин» есть.
- Выбор списка (форма, «Переместить», список по умолчанию, «Восстановить в список») — только списки, где я редактор, с разделами «Мои списки» / «Совместные» и аватарами.
- **Роль сменили, пока экран открыт.** Всё переключается само из снимка. Открытые формы закрываются с тостом «Вас сделали зрителем»:
  - правка желания и меню карточки — `WishSheet`;
  - форма добавления из этого списка — `WishActions`;
  - настройки списка — `ListActions`.

## Строка состояния iPhone
`AppLayout` на телефоне ставит фиксированную подложку цвета фона высотой `env(safe-area-inset-top)` (z-35 — ниже шторок и окон, выше содержимого). При прокрутке заголовки уходят под неё, а не под часы и значки сети. Viewport уже `viewport-fit=cover`.

# Исследование разбора ссылок (ТЗ 002)

**Дата:** 2026-11-23. Проверялось с сервера Supabase Edge Functions (Франкфурт, IP Amazon AWS) и с Mac владельца (российский домашний IP для сайтов `.ru`).

## Коротко для владельца

- **Wildberries — работает с сервера** через открытые файлы витрины: название, описание и фото есть всегда. **Текущей цены нет** — есть только история цен (последнее изменение бывает месяцы назад).
- **Обычные магазины — работают**, если у магазина нет защиты от ботов (oshadhi.store — всё: название, фото, цена, описание). **Lamoda закрыта** защитой, как маркетплейс.
- **Яндекс Маркет — с сервера не работает** (капча). С российского IP отдаёт всё, включая цену. С сервера достаём только артикул и «название латиницей» из адреса.
- **Ozon — не работает ниоткуда**: блокирует и сервер, и российский IP, и обычный браузер показывает пазл-капчу. Короткие ссылки `ozon.ru/t/…` тоже не раскрываются.
- **AliExpress — работает с перебоями**: с сервера получается название и фото, цены нет; иногда несколько минут подряд блокирует.
- **Картинки скачиваются с сервера** у всех, где удалось узнать их адрес (WB, Маркет, AliExpress, oshadhi).
- **Платный сервис для запуска не нужен**: если разбор не удался — создаётся частичная карточка (ссылка + что удалось достать), и это работает уже сейчас. Платный прокси с российским IP помог бы только Яндекс Маркету (Ozon он, скорее всего, не спасёт). Решение — за продуктом, варианты с ценами ниже.

## Выводы по источникам

### Wildberries — надёжность: **высокая** (без цены)
- **Страница товара:** 498 (JS-антибот) и с сервера, и с RU IP. Внутренний JSON `card.wb.ru/cards/v2|v4/detail` — 403 с обеих сторон.
- **Работает статичный CDN витрины** (без входа и без антибота, одинаково с сервера и с Mac):
  - `https://basket-{NN}.wbbasket.ru/vol{nm/100000}/part{nm/1000}/{nm}/info/ru/card.json` — название (`imt_name`), описание, бренд, категория;
  - `…/{nm}/images/big/1.webp` — первая картинка;
  - `…/{nm}/info/price-history.json` — история цен в копейках (точки по неделям, но **последняя запись — дата последнего изменения**, у тестовых товаров 2–6 месяцев назад; это не цена «сейчас» и, вероятно, без скидок WB).
  - Номер хоста `NN` зависит от `vol` (у нас: 14, 18, 20, 29 при vol 2106–5522). Таблица соответствия у WB меняется по мере роста артикулов. Варианты: перебрать хосты параллельно (≈40 запросов HEAD), или хранить известные диапазоны в коде и обновлять, с перебором как запасным вариантом.
- **Ссылки из приложения** — обычные полные (`/catalog/{nm}/detail.aspx?size=…`), коротких нет. Артикул достаётся из URL.
- **Стратегия:** артикул из URL → `card.json` + `images/big/1.webp`. Цену **не заполнять** (или заполнять из истории с пометкой — вопрос к продукту).
- **Запасной вариант:** если CDN не ответил — частичная карточка: ссылка + «Wildberries, арт. N».
- **Что увидит пользователь:** карточка с названием, фото и описанием, цена пустая (можно вписать вручную).

### Яндекс Маркет — с сервера надёжность: **низкая**
- **С сервера:** любая страница товара → 302 на `showcaptcha` (Yandex SmartCaptcha). То же для `m.market.yandex.ru`, для очищенного URL и для честного UA.
- **С RU IP:** 200, страница ~2 МБ, JSON-LD `Product`: название, картинка, цена в RUB, описание, канонический URL. После нескольких быстрых запросов (особенно с UA бота) с RU IP тоже бывает капча.
- **Короткие ссылки `market.yandex.ru/cc/…`** раскрываются и с сервера: первый 302 ведёт на `/card/{slug}/{id}?…`. Значит, артикул и slug (транслит названия) есть даже при капче.
- **Публичного JSON или oEmbed без входа не нашёл.** Картинки (`avatars.mds.yandex.net`) с сервера скачиваются, но их адрес есть только на закрытой странице.
- **Стратегия:** один запрос страницы; если пришёл JSON-LD — полная карточка; если капча — частичная. Никаких повторов и обходов.
- **Запасной вариант:** частичная карточка: ссылка + (по решению продукта) черновое название из slug, переведённое обратно в кириллицу («ochki-coin-whitelab» → «очки coin whitelab»), чтобы человек его поправил.
- **Что увидит пользователь:** почти всегда частичную карточку.

### Ozon — надёжность: **нет**
- Страница, мобильная версия `m.ozon.ru`, JSON `api/composer-api.bx` и `api/entrypoint-api.bx` → 307 → **403** с JSON `incidentId` (антибот Ozon). Одинаково с сервера и с российского IP, с любым UA. Во встроенном браузере Claude — пазл-капча «Сопоставьте пазл».
- **Короткая ссылка `ozon.ru/t/cxsdLU9`** → сразу 403, адрес товара не виден. Раскрыть её с сервера нельзя.
- Публичного способа без входа нет.
- **Стратегия:** не делать запрос к странице (бесполезен). Из полного URL взять артикул и slug.
- **Запасной вариант:** частичная карточка: ссылка + «Ozon, арт. N» и/или черновое название из slug. Для `ozon.ru/t/…` — только ссылка.
- **Что увидит пользователь:** частичную карточку, название и фото — вручную.

### AliExpress (`aliexpress.ru`) — надёжность: **низкая / средняя**
- **С RU IP:** всегда страница «punish» (`x5secdata`, антибот Alibaba).
- **С сервера:** после цепочки редиректов с установкой cookie (`aliexpress.ru` → `login.aliexpress.ru/…/aer-cookie/set-directly` → обратно) — полная страница 0,5 МБ: Open Graph название (с хвостом «на AliExpress»), картинка, канонический URL. **Цены в HTML нет** (подгружается скриптом), описание в OG — общий рекламный текст. Нужен обычный «cookie jar» и ручное следование редиректам — так ведёт себя любой браузер, это не обход защиты.
- **Нестабильно:** из ~20 запросов с сервера сначала около 7 подряд были успешны, потом ~8 подряд — «punish», через несколько минут снова работало.
- Внутренний JSON `aer-jsonapi/…/productData` → «punish».
- **Стратегия:** запрос страницы (без рекламных параметров, через cookie jar) → OG: название без «на AliExpress», картинка, URL.
- **Запасной вариант:** частичная карточка: ссылка + «AliExpress, товар N».
- **Что увидит пользователь:** чаще всего карточку с названием и фото без цены, иногда — частичную.

### Обычные магазины — надёжность: **средняя** (зависит от магазина)
- **oshadhi.store:** всё есть с сервера: название и картинка из Open Graph, цена и валюта из микроразметки (`itemprop="price"`), описание, `link rel=canonical`. JSON-LD нет. Название из OG/`<title>` с SEO-хвостом «купить в Петербурге — цена в интернет-магазине…» — стоит отрезать типовые хвосты («купить», «— цена», «в интернет-магазине») или брать `<h1>`.
- **Lamoda:** ведёт себя как маркетплейс. С сервера 403 «Запрос отклонен», с RU IP — JS-проверка Servicepipe, во встроенном браузере тоже «Запрос отклонен». Внутренний API → 403. **Частичная карточка.**
- **Стратегия:** JSON-LD `Product` → Open Graph (`og:*`, `product:price:*`) → микроразметка → `<title>`/`<h1>`. Cookie jar + до 5 редиректов, таймаут ~10 с.
- **Запасной вариант:** что удалось достать + ссылка; если ничего — домен магазина как название.

## Рекомендация для `parse-link` (этап 1)

1. **Определить источник по домену** и вынуть идентификатор из URL до любых запросов: WB — `catalog/{nm}`; Ozon — `product/{slug}-{id}`; Маркет — `card/{slug}/{id}`; AliExpress — `item/{id}.html`.
2. **Короткие ссылки** (`market.yandex.ru/cc/…`, а также неизвестные): идти по редиректам вручную (`redirect: 'manual'`), на каждом шаге проверять `Location` — если там уже узнаваемый адрес товара, брать артикул из него, даже если дальше капча. `ozon.ru/t/…` не раскрывается — сразу частичная карточка.
3. **Отдельные обработчики:** WB → CDN `wbbasket.ru`; Маркет → одна попытка страницы (JSON-LD), иначе частично; Ozon → без запроса, частично; AliExpress → страница + OG.
4. **Универсальный разбор** для остальных: JSON-LD → OG → микроразметка → `<title>`.
5. **Признаки неудачи** (сразу частичная карточка, без повторов): статусы 403/498/429, редирект на `showcaptcha`/`captcha`, `punish`/`x5secdata`, заглушки Servicepipe/«Запрос отклонен», JSON с `incidentId`.
6. **Картинка:** скачать с `Accept: image/webp,image/jpeg,image/png`, проверить сигнатуру файла, сжать до ~800 px и положить в Storage. Если не скачалась — карточка без фото.
7. **Ответ всегда успешный** для пользователя: карточка создаётся сразу (D-002), заполняется тем, что есть.
8. **Заголовки запроса:** обычная строка `User-Agent` браузера + `Accept-Language: ru`. Честный UA бота нигде не помог, а у Lamoda и Маркета сработал хуже. Подмены отпечатков, безголовых браузеров, решения капч — нет.

### Чистить ли ссылку и какую сохранять
- **Исходная ссылка сохраняется всегда как есть** (SPEC §4.5).
- **Для разбора** использовать очищенный адрес или собирать его из артикула: убрать `cpc`, `sponsored`, `at`, `sh`, `spm`, `utm_*`, `ru_algo_pv_id`, `scenario` и т. п. Очищенная ссылка Маркета разобралась так же, как исходная. Кроме того, `cpc` у Маркета — это токен рекламного клика: повторный запрос с ним может засчитаться как клик по рекламе.
- **Канонический URL** для кнопки «Перейти в магазин»: из `link rel=canonical` / JSON-LD, а если страница закрыта — собранный по шаблону: `https://www.wildberries.ru/catalog/{nm}/detail.aspx`, `https://www.ozon.ru/product/{id}/`, `https://market.yandex.ru/card/{slug}/{id}`, `https://aliexpress.ru/item/{id}.html`. При этом теряются выбранный размер (`size`) и продавец (`do-waremd5`) — это нормально при D-006 (вариант пишется в комментарии), но выбор, какую ссылку открывает кнопка, — вопрос к продукту.

## Нужен ли платный сервис

**Нет, для запуска не нужен.** С бесплатным тарифом получаем: WB (без цены), обычные магазины без защиты, AliExpress с перебоями. Маркет, Ozon и Lamoda — частичные карточки.

Если продукт захочет улучшить Маркет, варианты (ничего не подключено, цены ориентировочные, на ноябрь 2026 не проверялись):

| Вариант | Поможет | Цена (ориентир) | Минусы |
|---|---|---|---|
| Резидентный прокси с российскими IP (для запросов к Маркету из `parse-link`) | Маркет — вероятно да (с RU IP работает); Ozon, Lamoda — вероятно нет (блокируют и RU IP) | ~3–15 $ за ГБ; страница Маркета ~2 МБ → ~500 карточек на 1 ГБ | Новый внешний сервис, оплата из РФ, капча при частых запросах всё равно возможна |
| Свой VPS в России (как посредник) | Маркет — неизвестно: IP дата-центра Яндекс тоже может считать ботом | ~200–500 ₽/мес | Не проверено; ещё один сервер для поддержки |
| Сервисы парсинга с браузером (ScraperAPI, ZenRows и т. п.) | Возможно Ozon и Lamoda | от ~30–50 $/мес | Дорого для личного проекта; работа с российскими сайтами не гарантирована |

Бесплатные идеи для будущего (не проверялись, не для этапа 1):
- **Команда iOS «Быстрые команды» / ярлык «Поделиться»:** телефон пользователя сам скачивает страницу со своего российского IP и передаёт HTML в me:wish. Для Маркета это, по результатам Mac, сработало бы. PWA так сделать не может (браузер не даёт читать чужие сайты, CORS).
- **Отправка ссылки боту:** Telegram не передаёт боту содержимое превью ссылки, так что сам по себе бот разбор не улучшает.

## Риски

- **Смена разметки и путей CDN.** Особенно WB: формат `card.json`, таблица хостов `basket-NN`. Нужны понятные логи ошибок в `parse-link`.
- **Ужесточение защиты.** AliExpress уже блокирует периодически; WB может закрыть CDN-файлы `info/*.json` (сейчас это витрина, она открыта для всех).
- **Блокировка IP Supabase.** Все Edge Functions выходят с общих IP Amazon во Франкфурте — их блокировки мы не контролируем.
- **Условия использования сайтов.** Мы читаем публичные страницы по одной на действие пользователя, без массового сбора — риск низкий, но стоит держать нагрузку минимальной (без повторов и фоновых обходов).
- **Сжатие картинок на бесплатном тарифе.** Трансформация картинок в Supabase Storage, по документации, доступна только на платном плане. Сжимать придётся в самой функции (WASM-библиотека); лимит CPU на бесплатном тарифе — 2 с на запрос, декодирование большой webp/avif может в него не уложиться. Проверить в ТЗ этапа 1.

## Ограничения бесплатного тарифа (важные здесь)

- Edge Functions: 500 000 вызовов в месяц — с запасом.
- CPU-время — 2 с на запрос (ожидание сети не считается); общее время запроса — до 150 с. Самый долгий запрос пробы — 1,8 с по часам, по CPU — мало: разбор HTML на 2 МБ занимает десятки миллисекунд.
- Исходящий трафик функций входит в общий лимит egress (5 ГБ/мес) — страницы по 0,5–2 МБ при личном использовании не страшны.

## Как проводилась проверка

- Временная функция `parse-probe` (код — `docs/tech/parse-probe/`): ручное следование редиректам с cookie jar, запись цепочки, статусов, заголовков, размера; поиск антибот-признаков; разбор JSON-LD / OG / микроразметки / `<title>` / canonical; режимы `raw` (для JSON) и `image` (скачивание и сигнатура файла). Тот же модуль `probe.ts` запускался локально на Mac через Deno (`run.ts`) — запросы с Mac и с сервера одинаковые.
- Защита функции: секрет `PROBE_TOKEN` в заголовке. После исследования функция и секрет **удалены из облака** (`supabase functions list` — пусто).
- Выход сервера: `3.76.83.91`, Amazon AWS, Франкфурт. Выход Mac для `.ru` — российский IP провайдера; остальные сайты могли идти через VPN (Германия).
- Признак `captcha` у oshadhi.store — ложный (на странице есть скрипт капчи для форм). В `parse-link` ориентироваться на статус и конкретные заглушки, а не на слово «captcha» в HTML.

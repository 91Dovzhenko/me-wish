# Участники и приглашения (ТЗ 004-a)

Миграция `supabase/migrations/20261130100000_members_invites.sql`, Edge Function `supabase/functions/invite-preview`, тест `supabase/tests/rls_004a_members.sql` (38 проверок).

## Приглашения
- **Таблица `invites`:** `id, list_id, role, token_hash, created_by, created_at, expires_at (+7 дней), revoked_at`.
  - RLS: читать могут только редакторы списка. Прав на insert, update и delete у клиентов нет — всё через функции.
  - В Realtime: ссылки в «Участниках» обновляются у всех редакторов.
- **Токен:** 64 hex — два `gen_random_uuid()`, ~244 случайных бита.
  - В базе только `sha256` (`invite_token_hash()`).
  - Токен возвращается один раз из `create_invite`. Ссылка — `https://91dovzhenko.github.io/me-wish/i/<токен>`.
- **Функции** (security definer, с проверками):

  | Функция | Что делает | Кто |
  |---|---|---|
  | `create_invite(list, role)` → `(invite_id, token, expires_at)` | создать ссылку | редактор живого списка |
  | `revoke_invite(id)` | отозвать | любой редактор списка |
  | `find_valid_invite(token)` | приглашение не отозвано, не истекло, список не удалён | только внутри функций |
  | `invite_preview(token)` | минимум для карточки: название, иконка, цвет, режим обложки, число желаний, до 4 путей фото, роль, имя и аватар пригласившего | только `service_role` |
  | `accept_invite(token)` → `list_id` | вступить с ролью ссылки; существующую роль не понижает; ссылка многоразовая | вошедший |
- **Карточка до принятия:** Edge Function `invite-preview` (без проверки JWT — нужна и до входа).
  - По действующему токену вызывает `invite_preview` и подписывает фото обложки и аватар на 10 минут.
  - На любой другой токен отвечает `{status:'invalid'}`. Список целиком по токену не открывается.
- **«Скопировать» в «Участниках»:** токена в базе нет, поэтому скопировать ссылку ещё раз можно только на устройстве, где её создали. Токен запоминается в `localStorage` (`me-wish:invite-tokens`) до срока ссылки. На других устройствах у ссылки только «Отозвать».

## Принятие и контекст при входе
- Маршрут `/i/:token` — вне `RequireAuth` и `AppLayout` (`src/pages/InvitePage.tsx`).
  - Не вошёл — `LoginPage` с карточкой приглашения (1.5).
  - Вошёл — «Принять» (1.6) → `accept_invite` → переход на список с тостом «Вы присоединились к «…»» (1.8, тост передаётся в `location.state` и показывается в `MembershipWatcher`).
  - Уже участник (в том числе свой список) — сразу список.
  - Недействительна — 1.7.
- **Отложенное приглашение** (`me-wish:pending-invite`):
  - пока пользователь не вошёл, экран приглашения запоминает токен;
  - Google возвращает на главную (`redirectTo` — корень приложения) → `MembershipWatcher` один раз открывает `/i/<токен>`;
  - вход через бота идёт на этом же экране и после подтверждения сразу показывает «Принять». Если iPhone перезапустил установленное приложение, пока пользователь был в Telegram, вход закончится на `/login` → главная → снова `/i/<токен>`;
  - флаг `redirected` не даёт зациклиться (иначе «Назад» с экрана приглашения возвращал бы на него);
  - запись снимается при «Принять», «Не сейчас», недействительной ссылке, «уже участник»; срок — сутки.

## Участники
- `set_member_role(list, user, role)`, `remove_member(list, user)` — любой редактор, не себя (`22023 not_self`).
- `leave_list(list)` → `'left' | 'deleted'`:
  - последний редактор — список удаляется у всех (зрители могут оставаться);
  - свой единственный список, где я редактор, оставить нельзя (`P0001 last_list`) — в меню пункт неактивен с пояснением.
- `delete_list` — у всех участников. Последним считается только список, где я **редактор** (`editor_list_count`).
- `soft_delete_list` — общая часть: желания в корзину, список удалён, ссылки отозваны. Для каждого участника вызывается `fix_user_lists`. Участие в удалённом списке сохраняется — для корзины (D-117).
- `fix_user_lists(user)` — после «убрали», «понизили до зрителя», «удалили у всех»:
  - если у пользователя не осталось живого списка, где он редактор, создаётся «Мои желания»;
  - список по умолчанию — только живой, где он редактор (иначе первый такой по дате создания, D-117).

  Сам пользователь «Выйти» из последнего такого списка не может. Другой редактор может убрать его или понизить — тогда список создаётся автоматически, чтобы правило D-082 не нарушалось.
- Политика профиля: список по умолчанию — только свой живой, где я редактор.

## Приложение
- `AppData` грузит участников всех моих списков (`list_members`) и их имена/аватары (`profiles_public`).
  - У списка: `myRole`, `members` (я первым).
  - `editorListCount` — сколько у меня списков, где я редактор.
  - Realtime слушает весь `list_members` (раньше — только свои строки) и `invites`.
- Меню «•••» (`ListPage`):
  - редактор — «Редактировать», «Участники», «Удалить», «Выйти из списка» (если участников больше одного);
  - зритель — «Участники», «Выйти из списка» (2.20).

  «Участники» есть и в несовместном списке: только так можно пригласить (2.21).
- `features/members/`:
  - `MembersWindow` — 2.21–2.24, 2.22D;
  - `InviteWindow` — 2.25–2.26, «Поделиться» только если есть `navigator.share`;
  - `InviteCard` — 1.5–1.7;
  - `MembershipWatcher`;
  - `inviteLinks.ts`.
- `components/Panel` — шторка на телефоне и окно на компьютере. `Avatar` получил `tone` (цвет инициалов по id участника).
- **«Вас убрали из «…»» / «Список «…» удалён»:** `MembershipWatcher` сравнивает снимки.
  - Пропавший список, если его не убрало моё действие (`expectGone`), проверяется запросом в `list_members`: участие осталось → список удалён, нет → убрали.
  - Если пропавший список открыт — переход на главную.

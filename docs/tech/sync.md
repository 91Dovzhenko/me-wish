# Синхронизация между устройствами и обновление приложения (ТЗ 003-c-fix, D-105)

## Данные
Всё, что видно на экране (сводка главной, обложки и счётчики, боковое меню, сетка открытого списка), обновляется одним действием `sync()` в `src/data/AppData.tsx`:
перечитываются общие данные (`profiles`, `list_overview`, `dashboard_summary`) и растёт `wishesVersion` — экран списка перечитывает карточки. Пачка событий собирается в одно обновление (300 мс). Ответы, пришедшие не по порядку, отбрасываются — применяется только последний запрос.

Источники `sync()`:
1. **Supabase Realtime** (`postgres_changes`): `lists`, `list_items`, `wishes`, а также `list_members` и `profiles` своего пользователя (фильтр по id). Таблицы добавлены в публикацию `supabase_realtime` миграцией `20261125100000_realtime.sql`. Realtime проверяет RLS каждого подписчика: insert/update приходят только тем, кто может видеть строку. Об удалении строк (delete) Realtime сообщает всем подписчикам таблицы, но только первичный ключ — приложение по такому событию лишь перечитывает свои данные (сейчас жёстких удалений из приложения нет). После переподключения канала (статус `SUBSCRIBED` повторно) — тоже `sync()`, чтобы догнать пропущенное.
2. **Возвращение в приложение**: `visibilitychange` (видимо), `focus`, `pageshow`, `online` — не чаще раза в 2 секунды. Страхует, если соединение Realtime оборвалось в фоне (iOS усыпляет вкладки и PWA).

Данные обновляются тихо: без скелетонов, сетка показывает прежние карточки, пока не пришли новые.

### Бесплатный тариф
Realtime бесплатно: до 200 одновременных подключений и 2 млн сообщений в месяц — на семью с запасом. Одно открытое приложение — одно подключение.

## Код приложения (service worker)
**Причина рассинхронизации из отчёта владельца** («в меню 2, сетка пустая, обложка без коллажа»): на Mac работала **старая сборка 003-b** с новыми данными. Тогда service worker подключался простым скриптом (`injectRegister: 'script-defer'`): новая версия ставилась в фоне, но открытая вкладка продолжала выполнять старый код до ручной перезагрузки, а браузер сам проверяет обновления редко. В 003-b сетки и коллажа ещё не было, а счётчик брался из базы — отсюда «2» при пустом списке. База при этом отдавала владельцу все желания (проверено запросом с его правами: появления, желания и счётчик совпадают).

Теперь (`src/lib/pwa.ts`, `virtual:pwa-register`):
- обновление проверяется при запуске, при возвращении в приложение и раз в 30 минут;
- когда новая версия активировалась — страница перезагружается сама, **но не посреди формы**: если открыта шторка, окно, обрезка или диалог, перезагрузка ждёт, пока их закроют, или пока приложение свернут.

Один раз после выкладки этой версии старая вкладка, открытая заранее, может остаться на старом коде (у неё ещё старый способ регистрации) — после её перезагрузки всё работает само.

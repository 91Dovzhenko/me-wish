# Списки (ТЗ 003-b): удаление, формы, общие компоненты

## Удаление списка без потери желаний (D-082)
Миграция `supabase/migrations/20261124120000_lists_soft_delete.sql`.

- **Мягкое удаление:** `lists.deleted_at`. Удалённый список не возвращает ни `lists` (политика чтения требует `deleted_at is null`), ни `list_overview`, ни сводка главной.
- **Желания — в корзину:** при удалении всем его `list_items` без отметки ставится `deleted_at` (той же датой, что и списку). Уже лежавшие в корзине сохраняют свою дату. Сами `wishes` не трогаются.
- **Удалить можно только функцией `delete_list(p_list_id)`** (security definer):
  - проверяет, что вызывающий — редактор и список не удалён (иначе `P0002 list_not_found`);
  - не даёт удалить последний неудалённый список пользователя (`P0001 last_list`), строка профиля блокируется `for update`, чтобы два одновременных запроса не удалили оба последних списка;
  - у всех, у кого это был список по умолчанию, ставит первый оставшийся по `created_at`.
- **Напрямую нельзя:** политика и право `delete` на `lists` у клиентов убраны; `update` разрешён только по колонкам `title, description, event_date, icon, color, cover_mode` (column grants), так что `deleted_at` клиент не поставит. Каскад `lists → list_items` остался только для удаления аккаунта.
- **В удалённый список** нельзя добавить или переместить желание (`is_list_alive()` в политиках `list_items` insert/update), его нельзя сделать списком по умолчанию (политика `profiles`), его нельзя изменить.
- **Участие (`list_members`) удалённого списка сохраняется** — поэтому желания удалённого списка по-прежнему видны его участникам через существующие политики (`list_items`, `wishes`).

### Что это значит для корзины (003-e)
- Желания удалённого списка: `list_items` с `deleted_at is not null`, у которых список удалён. Отличить «удалено вместе со списком» от «удалено вручную» можно по `lists.deleted_at` (у списка он есть) — `deleted_at` у появления совпадает с ним.
- **Восстановить в другой список:** `update list_items set list_id = <выбранный>, deleted_at = null where id = …` — политика пропускает, если пользователь редактор обоих списков, а целевой не удалён (проверено в тесте). Предвыбор — `profiles.default_list_id`.
- **Название удалённого списка** («из «День рождения»») клиент сейчас прочитать не может: `lists` его скрывает. Для экрана корзины понадобится функция, например `trash_items()` (security definer, по участию), которая вернёт желание, дату удаления и название списка.
- Очистка через 30 дней (SPEC 5.7) — тоже 003-e: удалять `list_items` старше 30 дней, затем осиротевшие `wishes` и удалённые списки без появлений.

## Экран списка и данные
- Адрес `/l/<id>` (BrowserRouter, приём с `404.html` — `docs/tech/routing.md`).
- Экран берёт список из общих данных (`AppData` → `list_overview`), отдельного запроса нет. Пока данные грузятся — скелетон; если списка нет среди доступных (чужой, удалённый, несуществующий) — «Страница не найдена».
- В `list_overview` добавлены `active_count`, `done_count`, `done_sum` для сводки «Активные · Исполнено» на экране списка. «Исполнено» здесь — за всё время (на главной — за текущий год).
- После создания/изменения данные обновляются тихо (`refresh()`, без скелетонов), потом переход. После удаления — сначала переход на главную, потом обновление (иначе экран списка мигнул бы «не найдено»).

## Общие компоненты (пригодятся дальше)
- `components/TextField` — поле: обычное, фокус (чёрная рамка), ошибка (красная рамка, розовый фон, текст под полем), звёздочка, слот слева. На телефоне шрифт полей 16 px — иначе iOS увеличивает страницу при фокусе.
- `components/FormWindow` — шторка снизу (телефон) / окно по центру (компьютер). Esc, крестик и фон вызывают `onClose`; форма сама решает, спросить ли «Не сохранять?».
- `components/Dialog` — подтверждение (Esc и фон = отмена, фокус на «Отмене»).
- `components/Toast` — `useToast()({ text, kind?, action? })`; 4 с, с действием 6 с.
- `components/Menu` — `MenuPanel`, `MenuItem`, `MenuItemDisabled` (с пояснением), `MenuDivider`, хук `useDismiss` (клик снаружи, Esc не доходит до окна под меню).
- `components/DatePicker` — календарь, неделя с понедельника, сегодня лаймом, выбранный обведён, «Убрать дату».
- `hooks/useIsDesktop` — `matchMedia('(min-width: 64rem)')` для мест, где телефон и компьютер различаются устройством (шторка/окно, порядок кнопок).
- `features/lists/ListActions` — провайдер формы списка и удаления: `openCreate`, `openEdit(list)`, `askDelete(list)`; используется главной, боковым меню и экраном списка.

## Обложка
`components/Cover` принимает `photos` (до 4, новые первыми) и `coverMode`: 1 фото — целиком, 2 — две колонки, 3 — большое слева и два справа, 4 — 2×2; без фото или `icon` — иконка. Реальные фото подключатся в 003-c (нужно отдавать пути из Storage, например полем в `list_overview`). Проверка на подставных картинках — страница `/dev/covers`, есть только в `npm run dev`, в сборку не попадает.

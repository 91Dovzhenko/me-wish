# Корзина, профиль, автоочистка, общие состояния (ТЗ 003-e)

Миграция `supabase/migrations/20261127100000_trash_profile.sql`, Edge Function `supabase/functions/storage-cleanup`,
тесты `supabase/tests/rls_003e_trash_profile.sql` (30 проверок) и `supabase/tests/purge_003e.sql` (5 проверок).

## Корзина (`/trash`)
- **Данные:** `trash_items()` (security definer, по участию в списке, в том числе в удалённом) — желание, путь фото, список, его название, жив ли он, дата удаления. Нужна функция, потому что название удалённого списка `lists` не отдаёт. Приложение грузит корзину вместе с остальным снимком (`AppData`, четвёртый запрос), поэтому число в профиле и в меню всегда совпадает с экраном. Удаление из карточки сразу кладёт желание в корзину на экране.
- **«Удалится через N дн.»** — `trashDaysLeft()`: 30 дней от `list_items.deleted_at`, округление вверх, не меньше 1.
- **Восстановить:** список жив — `restore_list_item(id)` (из 003-d); список удалён — окно выбора (предвыбран список по умолчанию) и `restore_list_item_to(id, list_id)`. Обе функции security invoker: политика `list_items` пускает, только если пользователь — редактор старого и нового списка, а новый не удалён.
- **Очистить корзину:** `empty_trash(ids[])` (security definer) — удаляет только показанные появления и только в списках, где пользователь — редактор; затем желания без появлений и удалённые списки без появлений. Возвращает пути фото удалённых желаний — приложение сразу удаляет файлы (`removePhotos`). Что не удалилось (нет сети) — подберёт ночная уборка.
- Если желание уже лежит в выбранном списке (возможно только с этапа 5), восстановление упадёт на `unique (list_id, wish_id)` — пользователь увидит тост об ошибке.

## Автоочистка (SPEC 5.7)
Два задания `pg_cron` (расширение бесплатное):

| Задание | Когда (UTC) | Что делает |
|---|---|---|
| `me-wish-purge-trash` | 03:00 | `purge_trash()`: появления старше 30 дней в корзине → желания без появлений → удалённые списки без появлений. Возвращает число удалённых строк. |
| `me-wish-storage-cleanup` | 03:15 | `net.http_post` (pg_net) → Edge Function `storage-cleanup` |

**Файлы Storage.** Из SQL файлы удалять нельзя (триггер `storage.protect_delete`), поэтому — Edge Function:
- `storage_orphans()` (security definer, вызывать может только `service_role`) отдаёт до 1000 файлов, которые **не менялись больше суток** и на которые ничего не ссылается: в `wish-photos` — нет `wishes.image_path`, в `avatars` — нет `profiles.avatar_path`. Сутки — чтобы не задеть фото, загруженное в открытую форму.
- Функция удаляет их через Storage API пачками по 100 и возвращает `{ ok, removed: { bucket: n }, failed }`.
- Так подбираются: фото удалённых навсегда желаний (автоочистка, «Очистить корзину» без сети), брошенные при добавлении фото (003-c), старые аватары.

**Секреты** (в репозиторий не попадают):
- Edge Function: `CLEANUP_SECRET` (`supabase secrets set`). `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase передаёт функции сам.
- Vault: `me_wish_project_url` (адрес проекта) и `me_wish_cleanup_secret` (тот же секрет). Задание pg_cron читает их из `vault.decrypted_secrets`.
- Функция без проверки JWT (`verify_jwt = false` в `supabase/config.toml`, деплой с `--no-verify-jwt`): pg_cron не может выпустить токен пользователя. Вместо этого функция требует заголовок `x-cleanup-secret`; без него — 403.
- Сменить секрет: новое значение → `supabase secrets set CLEANUP_SECRET=…` и `select vault.update_secret((select id from vault.secrets where name = 'me_wish_cleanup_secret'), '…')`.

**Как проверено:**
- `purge_003e.sql` — данные со сдвинутой датой удаления (31, 29, 35, 40, 5 дней): старше 30 дней удалены вместе с желаниями и пустым удалённым списком, моложе — на месте, оба задания есть в `cron.job`. Транзакция откатывается.
- Edge Function вызвана без секрета (403) и с секретом. Команда задания `me-wish-storage-cleanup` выполнена вручную: в `net._http_response` ответ `200 {"ok":true,"removed":{"wish-photos":1,"avatars":1}}` — тестовые записи старше суток удалены, свежая осталась.
- Журнал запусков: `select * from cron.job_run_details order by start_time desc limit 10;` и `select * from net._http_response order by created desc limit 5;`.

**Бесплатный тариф:** Edge Functions — 500 000 вызовов в месяц, здесь один в сутки. pg_cron, pg_net и Vault бесплатны.

## Профиль (`/profile`)
- Телефон — по аватару в шапке; компьютер — меню внизу бокового меню → «Профиль» (на компьютере корзина и «Выйти» — только в меню, как на `Desktop-Profile`).
- **Имя:** `profiles.display_name`. Триггер `profiles_check_fields`: при смене имя обрезается по краям, пустое или длиннее 60 символов — ошибка `22023`. Проверка только при смене, потому что у старых профилей имя могло быть пустым.
- **Список по умолчанию:** `profiles.default_list_id` (политика уже пускает только свой неудалённый список). Форма добавления с главной берёт его (с 003-c).
- **Способы входа:** из сессии (`user.identities` и `app_metadata.providers`), только показ. Строка Telegram появится сама, когда у пользователя будет такой провайдер (003-f).
- Все изменения профиля — через `updateProfile()` в `AppData`: сразу на экране, затем запрос, при ошибке — откат и тост.

## Аватары
- Бакет **`avatars`**, закрытый, до 1 МБ, `image/webp` и `image/jpeg`. Путь `<user_id>/<uuid>.webp|jpg` (`is_avatar_path()`), у каждой загрузки новое имя.
- Обрезка — `ImageCropper` с `shape="circle"`; сжатие — `renderSquare(img, crop, 400)` → 400×400, WEBP (на iPhone — JPEG). Ограничения файла — как у фото желаний (JPG, PNG, WEBP, HEIC до 20 МБ).
- Порядок: загрузка нового файла → `avatar_path` в профиле → удаление старого файла. Профиль не сохранился — новый файл удаляется.
- **Кто видит** (`can_view_avatar()`): сам пользователь (своя папка) и участники общих с ним списков (`shares_list_with`, этап 2) — и только текущий аватар профиля. Загружать, перезаписывать и удалять — только в своей папке. Триггер не даёт вписать в профиль путь из чужой папки или с неверным именем (`42501`).
- Показ: `ProfileAvatar` — своё фото (подписанная ссылка из `avatars`) → фото Google (`avatar_url`) → инициалы. Шапка телефона, боковое меню и профиль используют его же.
- `src/lib/photos.ts` теперь работает с обоими бакетами (`usePhotoUrls(paths, bucket)`, `uploadPhoto(…, bucket)`, `removePhotos(paths, bucket)`); кэш ссылок — по «бакет + путь».

## Общие состояния
- **«Нет интернета»** — `OfflineBanner` в `AppLayout`, по `navigator.onLine` и событиям `online`/`offline`. Телефон — плашка поверх верха экрана (выше шторок и окон), компьютер — над контентом.
- **Ошибка сохранения** — один текст `SAVE_ERROR` («Не получилось сохранить — проверьте интернет») из `components/Toast.tsx`. Где показывается: добавление и редактирование желания (форма остаётся открытой, плюс строка над кнопкой), приоритет, статус, перенос, «Отменить» после удаления, создание и настройки списка, имя, список по умолчанию, восстановление из корзины. Удаление желания, удаление списка и очистка корзины — «Не получилось удалить — проверьте интернет». Аватар — строка ошибки под фото (`Mobile-Profile-AvatarError`).
- **Подсказка установки** — `features/install`: сама показывается один раз (`localStorage` `me-wish:install-hint-seen`), когда данные загрузились, только в Safari на iPhone/iPad (iPad с iPadOS 13+ — «Mac с сенсорным экраном») и не в режиме standalone. В профиле на телефоне — строка «Как установить на iPhone» (её нет на макете, но подсказка говорит «всегда есть в профиле»); в установленном приложении строки нет.

## Значок приложения (D-100)
`scripts/make-icons.swift` (macOS: `swift scripts/make-icons.swift`) рисует из знака ME:WISH (чёрный квадрат, лаймовое сердце `HEART_PATH`):
- `apple-touch-icon.png` 180 и `icon-maskable-512.png` — квадрат без прозрачных углов (iOS и Android скругляют сами), у маскируемой сердце внутри безопасного круга;
- `icon-192.png`, `icon-512.png` — скруглённый квадрат 80 % холста с прозрачными полями (сетка значков macOS — для Dock).

Название в манифесте, `<title>` и `apple-mobile-web-app-title` — «ME:WISH». iOS кэширует значок при добавлении: чтобы увидеть новый, ярлык надо удалить и добавить заново.

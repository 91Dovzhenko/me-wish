# Маршрутизация и прямые ссылки на GitHub Pages

**Решение (D-039):** `BrowserRouter` с `basename="/me-wish/"` (берётся из `import.meta.env.BASE_URL`, т. е. из `base` в `vite.config.ts`), чистые адреса без `#`.

## Проблема
GitHub Pages — статический хостинг. На адрес `/me-wish/l/abc` файла нет, и Pages отдаёт свой `404.html`.

## Как решено (приём «spa-github-pages»)
1. `public/404.html` попадает в корень `dist/`. GitHub Pages отдаёт его на любой несуществующий адрес.
   Скрипт в нём берёт путь после `/me-wish/` (вместе с `?query` и `#hash`) и делает
   `location.replace('/me-wish/?__redirect=<путь>')`.
2. `index.html` в `<head>` до загрузки React читает `__redirect` и через `history.replaceState`
   возвращает в адресную строку исходный адрес. React Router видит `/l/abc` и рисует нужную страницу.
3. Неизвестные адреса ловит маршрут `path="*"`: страница «Страница не найдена» со ссылкой на главную.

Если service worker уже установлен (повторный визит или PWA), он сам отдаёт `index.html` на любой
адрес внутри `/me-wish/` (`workbox.navigateFallback`), и шаги 1–2 не нужны.

## Особенности
- Первый ответ GitHub на прямую ссылку имеет HTTP-статус 404. Браузеру это не мешает, поисковики могут не
  индексировать такие страницы. Для приватных ссылок на списки это неважно.
- Параметр называется `__redirect`, чтобы не пересекаться с параметрами приложения.
- При смене домена или базового пути поменять `BASE` в `vite.config.ts` и строку `/me-wish/` в
  `public/404.html` и `index.html` (там пути прописаны вручную, потому что эти скрипты выполняются до сборки).

## Локальная проверка
В `npm run dev` Vite сам отдаёт `index.html` на любой путь. Чтобы проверить именно приём с `404.html`,
нужен статический сервер, который как GitHub отдаёт `404.html` на несуществующие пути и раздаёт `dist/` по `/me-wish/`.

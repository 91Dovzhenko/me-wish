## Сделано
- **Временная Edge Function `parse-probe`** задеплоена в проект `me-wish`: цепочка редиректов, итоговый URL, статус, заголовки, размер, признаки антибота, JSON-LD / Open Graph / микроразметка / `<title>` / canonical, цена и картинка. Режимы для JSON и для скачивания картинок.
- **Те же запросы с Mac** тем же кодом (`probe.ts` через Deno). Для `.ru` выход с Mac — российский IP провайдера (проверено).
- **Все 14 тестовых ссылок** прогнаны с сервера и с Mac (с обычным UA браузера и с честным UA бота). Результаты — в таблице `docs/tech/parsing-research.md`.
- **Короткие ссылки:** владелец прислал ссылки из приложений: `ozon.ru/t/…` (не раскрывается, 403), WB (полная ссылка с артикулом, коротких нет), `market.yandex.ru/cc/…` (раскрывается и с сервера до адреса товара, дальше капча).
- **Публичные способы по артикулу** (с разрешения владельца): у WB работает статичный CDN витрины (`card.json`, фото, история цен), внутренний JSON WB, Ozon, Lamoda, AliExpress — закрыт. У Маркета публичного JSON/oEmbed не нашёл.
- **Картинки с сервера** скачиваются: WB, Маркет, AliExpress, oshadhi. Для Ozon и Lamoda адрес картинки получить нельзя.
- **Стратегия, запасной вариант и надёжность** для всех 5 источников, рекомендация для `parse-link`, ответ про чистку ссылок, риски, лимиты тарифа — в документе.
- **Платный сервис для запуска не нужен.** Варианты с ценами описаны, ничего не подключено.
- **Тестовая функция и секрет `PROBE_TOKEN` удалены из облака.** Код пробы перенесён в `docs/tech/parse-probe/`, папка `supabase/functions/` пуста.

## Не сделано или сделано иначе, чем в ТЗ
- **Картинки Ozon и Lamoda не проверены:** страницы закрыты, адрес картинки взять негде. Проверено только, что их CDN отвечает без антибота.
- **Mac не полностью «российский»:** на Mac включён VPN с правилами. Сайты `.ru` идут с российского IP, а не-`.ru` (oshadhi.store, aliexpress.com, CDN картинок) могли идти через Германию. На выводы это не влияет: все маркетплейсы — на `.ru`.
- Ozon и Lamoda во встроенном браузере тоже показали капчу / «Запрос отклонен». Капчи не решал, отпечатки браузера не подменял, в аккаунты не входил.

## Технические решения
- Код пробы (`docs/tech/parse-probe/probe.ts`) можно взять за основу `parse-link`: ручные редиректы с cookie jar, разбор JSON-LD → OG → микроразметка → title, проверка сигнатуры картинок.
- Для WB нужен способ находить хост `basket-NN` по артикулу (таблица диапазонов + перебор как запасной вариант).
- Картинки запрашивать без AVIF (`Accept: image/webp,image/jpeg,image/png`): AliExpress отдаёт AVIF, если его принять.
- Новых зависимостей нет.

## Проблемы, риски, вопросы к продукту
- **Q-01 можно закрывать:** платный сервис не нужен; Ozon и Lamoda — частичные карточки, Маркет с сервера — почти всегда частичные, WB — без цены, AliExpress — с перебоями и без цены.
- **Цена WB:** заполнять ли цену из истории цен WB (последнее изменение, бывает месяцы назад, вероятно без скидок) с пометкой «≈», или оставлять пустой? Рекомендация: пустой.
- **Черновое название из адреса** для Ozon и Маркета (транслит slug → кириллица, например «ochki-coin-whitelab» → «очки coin whitelab»): показывать ли его в частичной карточке, чтобы человек поправил, или только ссылку?
- **Какую ссылку открывает «Перейти в магазин»:** очищенную каноническую (без рекламных `cpc`/`at`/`spm`, но и без выбранного размера/продавца) или исходную? Рекомендация: каноническую; исходная хранится всегда.
- **Маркет с российского IP работает полностью.** Если это важно — либо платный RU-прокси (ориентир 3–15 $/ГБ), либо в будущем «Быстрая команда» iOS, которая скачивает страницу с телефона. Решение за продуктом.
- **Риск для этапа 1:** сжатие картинок. Трансформация картинок в Supabase Storage — на платном плане; сжимать придётся в функции, а лимит CPU на бесплатном тарифе 2 с. Проверить в ТЗ этапа 1.
- **Риск:** WB может закрыть CDN-файлы, AliExpress блокирует периодически, IP Supabase общие (Amazon) — их блокировку мы не контролируем.

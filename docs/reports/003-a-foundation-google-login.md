## Сделано
1. **Дизайн-система** по `Spec-Foundations`: все цвета (12 основных + служебные) — CSS-переменные в `src/index.css`, проброшены в Tailwind; 8 цветов списков (фон, иконка, фон пустой обложки) из `ListIcon`/`Cover`; скругления 12/14/18/22/32; тени. Временные цвета и тёмная тема из 001 удалены, тема только светлая.
2. **Шрифты** Unbounded (логотип, заголовки экранов, «404») и Onest (весь остальной текст), с кириллицей — подключены локально (см. «Технические решения»).
3. **Компоненты:** логотип ME:WISH (знак + надпись, 4 размера по макетам), кнопки (лаймовая, тёмная, светлая с рамкой, текстовая ссылка + неактивное состояние), аватар (фото Google или инициалы на лавандовом градиенте; пока фото грузится или не загрузилось — инициалы), иконка списка (`ListIcon`, все 30 иконок перенесены из выгрузки), обложка (`Cover`: пустая с иконкой на цвете списка и с меткой даты), скелетоны (обложка, строка сводки, пункты меню). Для экрана входа — декоративная карточка желания с сердечками приоритета и меткой «Мечта».
4. **Раскладка телефона** (до 1023 px): шапка — логотип слева, аватар справа; плавающая лаймовая «+» внизу справа; нижней панели нет. Учтены вырезы iPhone (safe-area).
5. **Раскладка компьютера** (от 1024 px), вариант Б: контент прямо на сером фоне; боковое меню на белой скруглённой подложке, закреплено по высоте окна: логотип, «Главная», «Мои списки» (иконка, название, число желаний), «+ Новый список», внизу профиль (аватар + имя). Активный пункт лаймовый, при наведении — серая подсветка. При большом числе списков прокручивается только список списков.
6. **База:** миграция с пятью таблицами, ограничениями, индексами, RLS на всех таблицах, триггером первого входа, представлением для обложек и функцией сводки (подробно — ниже). Применена к облачному проекту `me-wish`.
7. **Экран входа** (телефон и компьютер): градиентный фон, две наклонённые карточки со своими простыми иллюстрациями (штатив с камерой, очки), ME:WISH, «Все желания — в одном месте», чёрная «Войти через Telegram» неактивна с меткой «скоро», белая «Войти через Google». Состояния «Входим…» (спиннер) и ошибка «Не получилось войти. Попробуйте ещё раз.» + «Попробовать ещё раз».
8. **Вход через Google:** Supabase Auth, PKCE, возврат на `…/me-wish/` с учётом базового пути. Без входа любой адрес ведёт на вход, после входа экран входа ведёт на главную.
9. **Главная по данным из базы:** сводка (телефон — две строки, компьютер — одна; у «Исполнено» галочка на лаймовой подложке), «Мои списки» с обложками, блок «С чего начать» (показывается, пока у пользователя нет ни одного желания). Загрузка — скелетоны по макетам. Если данные не загрузились — сообщение и «Попробовать ещё раз».
10. **Неактивные кнопки:** «+», «Добавить желание», «Добавить первое желание», «+ Новый список», обложки и пункты списков в меню видны как на макете, ничего не делают (подсказка «Скоро» при наведении).
11. **Выход:** на компьютере — меню профиля внизу бокового меню («Профиль», «Корзина» — неактивны, «Выйти» — работает); на телефоне — аватар → экран «Профиль» (назад, аватар, имя, «Выйти»).
12. **«Страница не найдена»** — по макетам (на компьютере — рядом с боковым меню, ни один пункт не активен).
13. Цвет темы PWA и `theme-color` — `#F4F4EF`; значок вкладки (favicon) — знак ME:WISH (чёрный квадрат с лаймовым сердцем).

## Изменения в базе данных
Миграция `supabase/migrations/20261123210000_stage1_schema.sql`:
- **Таблицы** (поля по DOMAIN §3): `profiles`, `lists` (иконка и цвет — из 30 и 8 значений, `cover_mode` `collage|icon`, по умолчанию `collage`), `list_members` (`editor|viewer`), `wishes` (цена — целые рубли ≥ 0, статусы `active|booked|purchased|gifted`, `completed_at`), `list_items` (приоритет 1–5, по умолчанию 3, `position`, `deleted_at`; пара список–желание уникальна). Полей будущих этапов нет.
- **Индексы** под RLS: участники по пользователю, появления по списку и по желанию, авторы.
- **RLS на всех пяти таблицах:**
  - списки, появления и участники видны только участникам списка; менять и удалять — только редакторам; зритель только читает;
  - желания видны участникам любого списка, где они лежат; менять и удалять — редакторам;
  - в свой список можно положить только своё желание (иначе можно было бы «подцепить» чужое по id);
  - профиль: свой — читать и менять; список по умолчанию можно поставить только из своих списков. Чужие профили — только имя и аватар через функцию `profiles_public()` и только при общем списке;
  - состав участников клиенту только для чтения (приглашения — этап 2);
  - анонимам таблицы недоступны совсем.
- **Создатель списка автоматически становится редактором** (триггер).
- **Неизменяемые поля** (автор, дата создания, желание в появлении) защищены триггером. `completed_at` ставится и сбрасывается автоматически при смене статуса.
- **Триггер первого входа** на `auth.users`: профиль (имя и аватар из Google), список «Мои желания» (сердце, лавандовый), участие редактором, `default_list_id`.
- **Представление `list_overview`** — списки с числом карточек и суммой для обложек и бокового меню (с RLS вызывающего).
- **Функция `dashboard_summary(p_tz)`** — «Активные» (`active`/`booked`, не в корзине) и «Исполнено в текущем году» (`purchased`/`gifted`, `completed_at` в текущем году по часовому поясу пользователя); сумма по `price`, пустые цены не считаются; желание в нескольких списках считается один раз.

## Как проверить
1. Откройте `https://91dovzhenko.github.io/me-wish/` на iPhone (после того как запушите коммит и пройдёт деплой). Экран входа: две карточки, ME:WISH, «Все желания — в одном месте», чёрная кнопка Telegram с меткой «скоро» и белая Google.
2. Нажмите «Войти через Google», выберите аккаунт; на предупреждении «Google hasn't verified this app» нажмите «Continue» (так и должно быть, D-099). Мелькнёт «Входим…», затем главная: «Активные 0 · 0 ₽», «Исполнено в 2026: 0 · 0 ₽», обложка «Мои желания — Пока пусто», блок «С чего начать», лаймовый «+».
3. Нажмите на аватар справа вверху → «Профиль» → «Выйти» → снова экран входа.
4. Откройте сайт на Mac и войдите. Слева белое меню: «Главная» лаймовая, «Мои желания 0», «+ Новый список», внизу ваше имя. Справа на сером фоне «Главная», сводка в одну строку, обложка и «С чего начать». Нажмите на имя внизу → меню → «Выйти».
5. Откройте `…/me-wish/abc` — «404 · Страница не найдена» с кнопкой «На главную» (без входа — экран входа).
6. Локально тоже можно: `npm run dev` → `http://localhost:5173/me-wish/`.

## Технические решения
- **Новые зависимости:** `@fontsource-variable/onest` и `@fontsource-variable/unbounded` — файлы шрифтов локально, вместо запросов к Google Fonts: работают офлайн в PWA, не нужен сторонний сервер. Других зависимостей нет.
- **Шрифты:** подключены в `src/index.css`, вариативные (одно начертание на все толщины). Service worker кэширует кириллицу и латиницу.
- **Иконки:** библиотека не подключалась. 30 иконок списков и иконки интерфейса — SVG-пути, перенесённые из выгрузки дизайна (`src/lib/listStyle.ts`, `src/components/Icons.tsx`).
- **Точка перехода телефон/компьютер — 1024 px**, как в ТЗ.
- **Как проверял RLS:** скрипт `supabase/tests/rls_stage1.sql` прогнан на облачной базе. Он создаёт двух пользователей (как после входа через Google), по очереди действует от их имени так же, как приложение (роль `authenticated` + идентификатор пользователя в токене), и проверяет 27 условий. Среди них: триггер первого входа (профиль, «Мои желания», участие, `default_list_id`) и сводка. Второй пользователь не видит списки, желания, появления, участников и профиль первого, не может их изменить или удалить, не может подцепить чужое желание к своему списку, добавить себя в чужой список, создать список от чужого имени и сделать чужой список своим «по умолчанию». Аноним не может читать таблицы. Результат: **27 из 27, ошибок нет**. Скрипт сам откатывает все изменения; после прогона проверил, что в базе не осталось ни пользователей, ни списков.
- **Миграция применена** через `supabase db query --remote` (у CLI нет пароля базы, `db push` его ждёт) и записана в историю миграций Supabase. Подробнее — `docs/tech/stage1-foundation.md`.
- **Вход:** PKCE, код обменивается вручную (`detectSessionInUrl: false`), чтобы показать «Входим…» и ошибку по макету. Служебные параметры сразу убираются из адреса.
- **Проверка экранов:** вход, ошибка входа, 404, адреса без входа — вживую в браузере на 390 px и 1440 px. Вошедшие экраны (первый вход, загрузка, много списков на 1024 px, меню профиля, профиль на телефоне, «Выйти») — с поддельной сессией и подменёнными ответами сервера в консоли браузера, потому что для настоящего входа нужен аккаунт владельца. Горизонтальной прокрутки на 390 px нет. При обычной загрузке ошибок в консоли нет.
- Сборка и `eslint` без ошибок. Остаётся старое предупреждение Vite «чанк больше 500 КБ» (в основном supabase-js), на работу не влияет; разбить сборку можно позже.

## Проблемы, риски, вопросы к продукту
- **Что осталось проверить после входа владельца:** настоящий вход через Google на сайте и локально и то, что после первого входа в базе появились профиль, «Мои желания», участие и `default_list_id`. Проверить в Supabase → Table Editor → `profiles` и `lists`, либо попросить меня в следующей сессии.
- **Вопрос к продукту — подпись пустого «Мои желания»:** «Пока пусто» (ТЗ) или «Список по умолчанию» (макет первого входа)? Сейчас «Пока пусто».
- **Вопрос к продукту — исполненные в корзине:** по ТЗ корзина исключается только из «Активных». Я исключил её и из «Исполнено в году»: удалённое желание обычно не хотят видеть в цифрах, а через 30 дней оно всё равно удалится и цифра бы «прыгнула». Если нужно иначе — одна строка в функции.
- **На этап 2:** чтение списков и желаний сейчас дополнительно разрешено их автору — это нужно, чтобы созданная строка сразу возвращалась клиенту. Когда появится удаление участников, это правило стоит пересмотреть (записано в `docs/tech/stage1-foundation.md`).
- Иконки PWA (домашний экран) пока временные фиолетовые из 001: в ТЗ их не было.

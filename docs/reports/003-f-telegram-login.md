# 003-f — Отчёт Claude Code: вход через Telegram

**Дата:** 2026-11-24  **ТЗ:** `docs/tasks/003-f-telegram-login.md`  **Коммит:** «003-f: вход через Telegram — своя кнопка, проверка подписи в Edge Function, сессия Supabase, Telegram в профиле»

## Сделано
1. **Кнопка «Войти через Telegram»** активна, метки «скоро» нет.
   - Кнопка своя, по макету (`Mobile-Login`, `Desktop-Login`); стандартный виджет Telegram не нужен.
   - Вход идёт через переадресацию на `oauth.telegram.org/auth` (`bot_id`, `origin`, `return_to`). Результат возвращается в адресе (`#tgAuthResult=…`).
2. **Проверка на сервере** — Edge Function `telegram-auth`:
   - подпись по алгоритму Telegram (HMAC от токена бота);
   - данные не старше 5 минут;
   - находит или создаёт пользователя Supabase для этого `telegram_id`;
   - выдаёт одноразовый токен входа, браузер меняет его на обычную сессию Supabase.

   Дальше всё как с Google: RLS, профиль, списки.
3. **Первый вход:**
   - профиль с именем «Имя Фамилия» и фото из Telegram (если фото есть);
   - список «Мои желания» — список по умолчанию;
   - в профиле `telegram_id`.

   Повторный вход открывает тот же аккаунт.
4. **Состояния** по макетам: «Входим…» после возврата из Telegram; «Не получилось войти» с «Попробовать ещё раз» — при неверной подписи, устаревших данных, отказе или испорченном ответе. «Попробовать ещё раз» повторяет тот способ, которым входили: Telegram или Google.
5. **Профиль → «Способы входа»:** у вошедших через Telegram — «Telegram · Вход выполнен через него», без кнопок.
6. **Метка «скоро»** убрана.
7. **Переменные сборки:**
   - `VITE_TELEGRAM_BOT_ID=9170631172`, `VITE_TELEGRAM_BOT_NAME=me_wish_bot` добавлены в локальный `.env` (он не коммитится);
   - `.env.example` обновлён;
   - обе переменные передаются в сборку в `.github/workflows/deploy.yml`.

## Как устроен вход
1. Кнопка → `oauth.telegram.org` → пользователь подтверждает вход в Telegram.
2. Telegram возвращает на `https://91dovzhenko.github.io/me-wish/#tgAuthResult=…` с подписанными данными.
3. Приложение показывает «Входим…» и отправляет данные в Edge Function `telegram-auth`.
4. Функция проверяет подпись токеном бота и свежесть. Затем находит или создаёт пользователя через Admin API: у него служебная почта `telegram-<id>@me-wish.invalid`, на которую письма никуда не уходят.
5. Функция выпускает одноразовый токен входа (`generateLink` → `hashed_token`).
6. Браузер вызывает `verifyOtp` и получает обычную сессию Supabase.
7. В браузер попадает только одноразовый токен, а ключ `service_role` и токен бота остаются на сервере. Это бесплатно и без внешних сервисов.

Подробно — `docs/tech/telegram-login.md`.

## Что нужно сделать вам в GitHub (до пуша)
1. Откройте репозиторий на github.com → вкладка **Settings**.
2. Слева: **Secrets and variables** → **Actions**.
3. Вкладка **Variables** (не Secrets) → кнопка **New repository variable**.
4. Name: `VITE_TELEGRAM_BOT_ID`, Value: `9170631172` → **Add variable**.
5. Ещё раз **New repository variable**: Name `VITE_TELEGRAM_BOT_NAME`, Value `me_wish_bot` → **Add variable**.
6. В списке должны быть четыре переменные: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_TELEGRAM_BOT_ID`, `VITE_TELEGRAM_BOT_NAME`.
7. После этого запушьте коммит в GitHub Desktop. Сборка пройдёт сама.

Если запушить без переменных, кнопка Telegram покажет «Не получилось войти». Тогда добавьте переменные и перезапустите сборку: Actions → последний запуск → **Re-run all jobs**.

## ⚠️ Аккаунты Google и Telegram — разные
- Пока нет привязки второго способа входа (этап 3), вход через Telegram и вход через Google — **два отдельных аккаунта**.
- Если вы (аккаунт через Google) войдёте через Telegram, откроется **новый пустой аккаунт** со своими «Моими желаниями». Ваши списки останутся в аккаунте Google.
- Так и должно быть на этом этапе. Ничего автоматически не объединяется.
- Жене нужно всегда входить через Telegram, вам — через Google, тогда всё будет на месте.

## Изменения в базе данных
Миграция `supabase/migrations/20261128100000_telegram_login.sql` применена к облачному проекту и записана в историю.
- `profiles.telegram_id` (bigint, уникальный, может быть пустым).
- **Права:** клиент теперь может менять в профиле только имя, аватар и список по умолчанию. `telegram_id` ставит только сервер. Иначе можно было бы вписать себе чужой Telegram и перехватить чужой вход.
- Триггер первого входа: имя и фото Telegram берутся из данных пользователя. Из служебной почты имя не берётся.
- Edge Function `telegram-auth` выложена (с вашего согласия). Работает с ключом сервера только внутри Supabase.
- **Защита от подмены почты:** вход выдаётся только аккаунту, у профиля которого этот `telegram_id`. Если кто-то заранее зарегистрирует служебную почту чужого Telegram, функция откажет.
- **RLS-тест** `supabase/tests/rls_003f_telegram.sql` — **6/6**:
  - первый вход с данными Telegram;
  - имя не берётся из почты;
  - `telegram_id` уникален;
  - клиент не может поставить себе `telegram_id`;
  - имя и аватар менять можно;
  - чужой профиль не виден.

  Старые тесты проходят: 27/27, 25/25, 28/28, 30/30, 30/30 и автоочистка 5/5.

## Что проверено
- **Самопроверка на сервере.** Временная функция подписала тестовые данные токеном бота прямо в Supabase, токен наружу не уходил. После проверки функция удалена, тестовый пользователь тоже.

  | Проверка | Результат |
  |---|---|
  | Первый вход | 200, новый пользователь, сессия получена |
  | Профиль после первого входа | «Тест Самопроверка», `telegram_id` записан, по умолчанию «Мои желания» |
  | Повторный вход | 200, **тот же пользователь** |
  | Повторное использование токена входа | отклонено |
  | Изменённое имя при старой подписи | 401 `bad_signature` |
  | Поддельная подпись | 401 `bad_signature` |
  | Данные 10-минутной давности | 401 `expired` |
  | Лишнее поле | 400 |
  | Без подписи | 401 |

  Первый прогон нашёл ошибку: `telegram_id` не записывался, и повторный вход не находил аккаунт. Исправил и прогнал снова — всё прошло.
- **Экран входа в браузере** (на тестовых данных):
  - кнопка уводит на `oauth.telegram.org` с правильными параметрами;
  - с адресом `91dovzhenko.github.io` Telegram показывает «Войдите… для 91dovzhenko.github.io и ME:WISH» — бот и домен настроены верно;
  - возврат с отклонённой подписью — «Не получилось войти», «Попробовать ещё раз» снова ведёт в Telegram;
  - возврат с принятыми данными — «Входим…» → главная;
  - кириллица в имени разбирается правильно;
  - профиль показывает Telegram;
  - вход через Google не менялся (кнопка и обмен кода те же).
- **Токена бота нет** ни в сборке, ни в коде, ни в истории git (поиск по шаблону токена). В сборке только публичный id бота.
- Сборка, линтер — чистые; в консоли только ошибки WebSocket тестовой заглушки.

## Как проверить
1. Добавьте переменные в GitHub (инструкция выше) и запушьте.
2. На iPhone жены откройте `https://91dovzhenko.github.io/me-wish/` в Safari → «Войти через Telegram».
3. Введите номер, подтвердите вход в Telegram.
4. Мелькнёт «Входим…», откроется главная с её именем и пустыми «Моими желаниями».
5. Профиль → «Способы входа»: Telegram.
6. Выйдите и войдите снова — тот же аккаунт.
7. Повторите в установленном приложении (с экрана «Домой») и на Mac.
8. На своём устройстве войдите через Google — всё как раньше, данных жены не видно.

Если на iPhone вход «застрянет» во встроенном окне (в нём войдёт, а в самом приложении нет), напишите мне. Запасной вариант — вход через бота одноразовой ссылкой, но для него нужен вебхук бота (этап 3).
- **«Отмена» на странице Telegram** пытается закрыть окно. Если окно не закрылось, нажмите «Назад» — снова будет экран входа.
- Если когда-нибудь смените домен сайта, его нужно поменять и в @BotFather (`/setdomain`).
